# 「保存できたか分かりづらい」を調べる

架空の設定画面を使った作例です。利用者は通知の設定を変更し、その変更が残ると分かれば次の作業に進めます。

| 見つかった兆候 | 調べる事実 | 事実に応じた改善案 |
| --- | --- | --- |
| 押した直後に何度も押す | 受付から応答まで何が表示されるか。同じ操作が重複して処理されるか。 | 受付が伝わっていなければ、操作の付近で処理中と示す。重複操作に副作用がある場合は、実装でも重複を防ぐ。 |
| 完了後も設定画面を開き直す | 確定した設定と画面の表示が一致するか。「保存済み」が何に掛かると理解されたか。 | 確定を確認してから、保存された対象や現在値を示す。古い保存結果を後続の変更へ適用しない。 |
| 失敗しても次へ進んでしまう | 拒否・通信断・結果不明で表示がどう変わるか。入力が残り、状態確認や修正ができるか。 | 結果不明を成功と表示せず、確認手段を示す。確実に失敗した場合は、入力を保ち、理由に応じて修正や安全な再試行へ案内する。 |

原因によって、[システム状態の可視性](../knowledge/system-status-visibility/KNOWLEDGE.md)と[エラーからの回復](../knowledge/error-recovery/KNOWLEDGE.md)のどこを適用するかが変わります。どの原因かまだ分からない場合は、「設定を変えたとき、押す前と押した後のどちらで迷いましたか」と聞くか、一度操作を見ます。

**AIが検査すること。** 成功応答を遅らせ、確定前に「保存済み」と出ないことを確かめます。成功後は再読込して保存値と表示を照合します。入力エラー、通信断、応答喪失を再現し、入力の保持と、状態に合った文言および操作を確認します。Webで該当する動的な表示が支援技術へ通知できることも確かめます。

**人に確かめてもらうこと。** 「通知の設定を変更して、終わったと思ったら次の作業に移ってください」と頼みます。操作を教えず、どこで止まるか、確定したと思った時点、失敗時にどこへ進むかを観察します。「変更は保存されたと思いますか」と聞くと、理由を詳しく言語化できなくても理解を確認できます。実施できなければ、報告では機械検査の結果と、人への効果が未確認であることを示します。[ユーザビリティテスト](../knowledge/usability-testing/KNOWLEDGE.md)
