# Quality gates

`runStaticQualityGates` and `runBrowserQualityGates` in `packages/core/src/quality-gates` inspect the five files emitted by `buildPrototype`. Pass the generated directory and its trusted local root. Supply `ArtifactStore` to resolve exact source locks and approved DTCG tokens; without it those checks are `UNVERIFIED`. The optional exact Product UI Contract reference checks identity, type, and approval. Its semantic consistency remains a `CONCERN` pending review.

For a standalone bundle, the saved plan's `outputPath` must resolve from the trusted root to the inspected directory. For a `buildPrototypeModes` bundle, the plan keeps its authored path relative to the published comparison directory. Both gate runners accept that base only when the inspected directory is the named Current or Proposed slot immediately inside the comparison directory and the regular `mode-plan.json` and `comparison.json` files agree on the mode-plan digest, exact scenario and contract references, choice and decision context, both slot paths and render-plan digests, and the saved Current or marked Proposed plan. A rejected or unresolved fallback requires an explicit `proposed: null` in the comparison manifest. Moving the whole trusted root with its relative contents intact is supported when the caller supplies the new root and bundle directory; moving only a bundle or comparison directory within a root fails the location check. Inconsistent comparison metadata also fails; the ordinary trusted-root containment and bundle-file checks still apply.

The static runner checks plan/manifest identity, source locks, approved artifact roles and scenario dependencies, token compilation, html-validate, ESLint, and Stylelint. It validates the saved plan's builder-supported states, fixtures, layout bounds, semantic tags, labels and local links before dereferencing fields. A transient source read or compiler outage is `UNVERIFIED`; an observed lock, role, or approval mismatch is `FAIL`. The browser runner serves only an in-memory copy of the inspected local files on loopback and blocks off-origin requests. It uses Chromium by default or an explicitly supplied Playwright project browser, and records the actual engine and viewport. Firefox mobile is viewport/touch emulation without the unsupported `isMobile` context option. It checks rendered state completeness, every declared transition and same-session repeats where a return path exists, declared fragment links and targets, axe findings in reached states, first Tab focus, and document overflow. Empty or malformed plans cannot produce a zero-observation `PASS`. A single valid state with neither transition controls nor fragment links has navigation `N/A` with a reason. A browser transport loss during execution is `UNVERIFIED`; an observed broken interaction is `FAIL`. Each finding has an independent state and severity, exact bundle target digest, evidence file names, conditions, and limits.

For a saved [responsive program](prototype-responsive.md), the static runner applies the builder's finite structure validation to the actual `plan.json` bytes. The browser runner derives desktop and mobile expected action/link trees, then checks the emitted final DOM order after every operation, replacement surface, keyboard disclosure open/close, and state/focus across both resize directions. Its viewports straddle the locked breakpoint, including the supported 320px and 1600px bounds. A primary action inside a closed disclosure uses its keyboard-focusable summary as the mobile focus path. `responsive-transform` reports the number of observed operations against the exact bundle digest. An observed mismatch is `FAIL`; an interrupted browser run is `UNVERIFIED`. Structural checks do not prove the author's semantic continuity claims or empirical mobile usability.

These runners only inspect. They do not publish or approve an artifact. Synthetic fixture results do not establish actual user success, visual quality, full keyboard accessibility, or WCAG 2.2 AA conformance. Re-run checks after any byte changes because the bundle digest changes. Use `pnpm exec vitest run packages/core/src/quality-gates/quality-gates.test.ts` and `pnpm exec playwright test apps/demo-lab/tests/quality-gates.spec.ts --project=chromium-desktop --project=chromium-mobile` to verify the generated-output gates.

The mode-bundle browser regression runs through the repository's Playwright projects: `pnpm exec playwright test apps/demo-lab/tests/mode-quality-path.spec.ts --project=chromium-desktop --project=chromium-mobile`. It inspects actual generated Current and Proposed bundles on both desktop and mobile viewports. The browser CI runs it alongside the other generated-output checks; the unit suite remains runnable before browser binaries are installed.

The current builder emits one document `<main>` landmark containing its generated state views. The generated fixture passes `html-lint`; a second `<main>` in the saved output produces a `no-multiple-main` failure. Both runners are exported from `@mimic/core`.
