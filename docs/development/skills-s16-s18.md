# S16–S18 quality Skill packages

[9UI-108](https://linear.app/9uile/issue/9UI-108/implement-design-critic-knowledge-curator-and-experience-validation) adds the declarative [S16](../../skills/s16-design-critic/), [S17](../../skills/s17-knowledge-curator/), and [S18](../../skills/s18-experience-validation/) packages. Each has a manifest, reasoning procedure, schema-shaped illustrative artifact, and executable scenario data. The Vitest bridge loads each package with `loadSkillPackage` and invokes it through `runSkillPackage` using a deterministic injected executor and one real shared file workspace. This verifies declared I/O, exact Run and lock routing, blocked zero-output behavior, reuse and approval boundaries. It does not execute the prose as an AI model or establish reasoning quality.

S16 records separate qualitative findings with state, severity, affected action and narrow provenance. S17's five dispositions are decision alternatives in the existing `decision` artifact; promotion remains pending human approval. S18 uses `validation.state: UNVERIFIED` for plans or absent empirical evidence and maps supported, mixed and unsupported observations to scoped PASS, CONCERN and FAIL only with inspected evidence. Example evidence URIs and digests are illustrative, never verified observations or real locks. The S18 observation file is explicitly synthetic and only tests the supported/mixed/unsupported mapping; no generated result from it is user research.

The static manifest expresses target/source variants through named `alternatives[].oneOf` groups. S16 accepts scenario, design direction, journey, and design-system asset targets and requires task/risk context from a task model, problem profile, or bounded brief; S17 accepts evaluation, validation, problem-profile, and reference-selection sources; S18 accepts scenario, journey, and design-direction targets. An unidentified prototype file remains optional evidence rather than an invented artifact type. The loader currently rejects declaring one artifact type both as a target alternative and as optional context; callers must supply the selected exact target plus the other declared context, and report unavailable same-type context as a gap. Further target types require a manifest revision. The human-gate enum has `organization-promotion` but no product-promotion value; S17 still routes both product and organization promotion to human review and does not commit either. No package acquires tools or runs its own test files: the trusted injected executor reads scenario data. The runtime checks shape, origin, exact locks and authority but cannot judge evidence relevance, qualitative critique, or actual participant observations. There is no typed composition plan, knowledge graph, validation plan, or generic revision-request artifact; route revision requests through the Orchestrator and keep non-typed detail in linked evidence and permitted prose. Do not extend schemas or mislabel `system-request` to close those gaps.
