# S08–S09 design intelligence implementation

S08 profiles one Experience Domain using locked task, contract, and domain inputs. The four content arrays remain the approved `problem-profile` shape; narrow provenance carries traceability. S09 reads a local graph source supplied for a Run and returns the approved `reference-selection` shape. This graph source is not a new artifact type or the future public seed library (9UI-109).

The pure `retrieveDesignReferences` API validates typed graph edges and traverses trait → principle → space → case → mechanism → principle. Patterns and failure modes attach to principles. It requires an assessed fit and distance for each case, enforces role thresholds, excludes rejected, disconnected, and duplicate-assessed candidates, and orders candidates by new principle/mechanism coverage, fit, maturity, usage, then stable ID. Cases omitted by a portfolio limit remain explicit exclusions. This is a deterministic aid to reasoning, not an empirical relevance model. Its `blocked` result has zero outputs when no candidate qualifies; the schema requires at least one reference in a successful selection.

The package examples are synthetic. They show schema-valid envelopes, provenance, and transfer limits, not studied cases. Runtime tests bind exact artifact locks and S08 claim provenance through `loadSkillPackage` and `runSkillPackage`, exercise changed graph and contract inputs, and verify a blocked S09 run produces no reference-selection artifact. The source format and public contents can evolve with 9UI-109 without changing the v1 artifact schemas.
