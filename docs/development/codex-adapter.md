# Official Codex adapter boundary

`apps/cli/src/agent/codex.ts` targets the unmodified official Codex CLI `0.160.0`, an absolute executable, an explicit native-login environment, and one workspace. Other versions are unsupported. It never extracts tokens, reads authentication files, performs login, grants permissions, purchases credits, calls private HTTP endpoints, or changes backend. Raw official stderr, configuration, account identifiers and model reasoning stay out of diagnostics.

## Billing and explicit one-shot permission

Normal `CodexExecutor.start()` and `startExecution()` retain the subscription-only billing hold. Recognized ChatGPT login reports `entitlement.status: "unconfirmed"`; login does not prove that existing credits cannot be consumed. API authentication and API-key, provider-endpoint, proxy and process-injection environment overrides cannot dispatch. The official [personal-plan credit documentation](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-personal-plans) explains additional credit use. Current account metadata established ChatGPT authentication and `hasCredits: true`, without proving an existing-credit exclusion control. No actual model call is claimed.

An explicitly authorized existing-credit-risk test is a separate policy, not a fabricated confirmed subscription-only entitlement. `createCodexCreditRiskPermit(port, request, signal?)` requires a trusted application/coordinator port that atomically consumes a recorded actual user decision. The port is never supplied by model output, configuration or a work envelope. A permit is an opaque in-memory object bound to request ID, explicit model, canonical workspace, prompt SHA-256 and expiry (at most five minutes). Repeated receipts, forged objects, changed scope and expired permission fail closed.

`startAuthorizedOnce(request, outputSchemaPath, permit, signal?)` consumes the permit before asynchronous inspection, safety checks or spawn. Failure, timeout and cancellation do not restore it. Request primitives/settings are copied before awaits. The method uses the existing native ChatGPT login, checks the recognized runtime, verifies the fixed profile through official metadata, then connects one production subprocess to the incremental decoder. Cancellation reaches decision lookup, metadata processes, the final pre-spawn guard and generation process group. The trusted outer session factory permits one attempt and records this policy separately in its checkpoint; normal entitlement guards remain unchanged. There is no JSON or public CLI flag that unlocks this mode. A real permit must not be issued until the user actually authorizes that risk.

One attempt means one fresh CLI invocation; it is not a claim of one backend HTTP request. The official [provider source](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/model-provider-info/src/lib.rs) defaults to `request_max_retries = 4` and `stream_max_retries = 5`. Disabling unbounded connection retries does not remove these bounded transport retries. Mimic never automatically reissues this generation. Prompt, output and process duration are bounded, with a default 30-second generation timeout and a maximum of 60 seconds.

## Fixed safe invocation and metadata gate

`createCodexGenerationProfile(options, request, outputSchemaPath)` prepares a fresh ephemeral `exec` invocation. The schema must be a regular workspace-contained file after lexical and realpath checks. Input arrives on stdin. The profile fixes ChatGPT authentication, built-in OpenAI provider, Standard (`service_tier = "default"`), approval policy `never`, and a named `mimic` permission profile extending `:read-only` with direct network disabled and native authentication/SSH/AWS directory read denials. It ignores user config and rules, disables shell, plugins, apps, hooks, hosted web/image/browser/computer tools, memory, multi-agent, skill installation and auxiliary switching, and suppresses notification commands.

Project settings use a whole-table TOML override, not quoted dotted CLI path keys. `project_root_markers = []` restricts project configuration discovery to cwd, whose fixed untrusted setting suppresses that layer. It does not disable all Git discovery. Native global `CODEX_HOME/AGENTS.override.md` and `AGENTS.md` are independent of project settings: stat-only checks accept absent or empty regular files and reject nonempty files, symlinks and other errors. Their contents are not read by this adapter. Host skill discovery and bundled skill installation are disabled.

`inspectCodexGenerationSafety(options, request, outputSchemaPath)` performs the same metadata-only safety preflight without issuing a permit or invoking a model. It sends only `initialize`, `initialized`, `config/read` with cwd and layers, and `configRequirements/read`. The public app-server reads user config while `exec --ignore-user-config` excludes it. The safety projection therefore follows the versioned [loader](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/config/src/loader/mod.rs) and [merge](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/config/src/merge.rs) semantics: reverse the supplied high-to-low layer order, preserve ties, exclude user/disabled layers, reject active project layers, retain system/cloud/managed layers, recursively overlay maps and replace scalar/array values. The four supported structured feature representations retain their `enabled` semantics. Unknown/incomplete layers, unsupported merge forms, unexpected precedence, missing session flags and prototype keys fail closed.

The API omits packaged defaults. This safety projection relies on the trusted stock `0.160.0` executable and its versioned [embedded defaults](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/config/defaults.toml), which contain no MCP, provider or permission overrides; stock exec/app-server do not expose a packaged-default injection flag. This is not certification of a patched binary or arbitrary internal host. Remaining MCP/provider maps, altered endpoints/catalogs/instructions, additional write/network authority, re-enabled features and unsafe fixed controls are rejected. Requirements are checked separately: only no policy, or exact `allowedLoginMethods: ["chatgpt"]` with all other fields null, is accepted. Other managed requirements stop for explicit compatibility work. Diagnostics identify only fixed control names.

The profile fixes `features.code_mode_host = { enabled = false, disable_in_process_fallback = false }`. The official [thread manager](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/thread_manager.rs#L557) then selects the disabled CodeMode provider; stock exec does not inject another provider. Model-advertised CodeMode tools may remain registered, but their host cannot execute cells. Harmless clock and local question events are not universal blockers. `apply_patch` registration is independent of shell controls; the [patch safety guard](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/safety.rs#L67) rejects writes under read-only/no approval. Complete tool absence is not claimed and `toolRestriction` remains false. Rejecting unexpected JSONL tools is detection after output, not the preventive boundary; the fixed host/config/permission restrictions provide that boundary.

## Candidate output and static authority

Production startup uses `executeOfficialProcess.onStdout` and `CodexJsonlDecoder` for bounded fatal UTF-8 JSONL decoding, normalized stops, cancellation and timeout. Terminal success is withheld until EOF and exit zero. Reasoning and raw diagnostics are hidden. The production path accepts a structured JSON object for a small smoke; the decoder's default work-envelope mode still validates `{ artifacts, work }`. Neither mode authorizes tools, approval or commit.

One turn may contain distinct completed `agent_message` items. The decoder counts their output bytes, but only the last completed message at `turn.completed` is validated as the work candidate. An earlier valid message cannot rescue an invalid final message; repeated item IDs, incomplete items and a missing clean terminal still fail closed. The earlier S05 real attempt recorded a second `agent_message` after an observed output and stopped at protocol validation. Its redacted diagnostic does not prove which sequence guard rejected that item, so the frozen attempt remains an unknown outcome.

`prepareCodexSubmission` checks the candidate's Run/task identity and contained paths and returns serialized work plus only `submit <run> --task <task> --package <package> --work <file> --root <workspace> --json`. It writes no files. The session owns immutable saving/checkpoints. Core's existing static Skill path validates schemas, realpath containment, digests, exact dependencies, immutable retry reservations and review gates. Approval and commit remain human actions; no `CliHost.executeSkill` bypass is constructed.

Fresh ephemeral execution has no persisted native session, so native resume is unsupported. Mimic checkpoint recovery reconciles accepted submissions and does not regenerate accepted work. The integrated launcher/decoder/static handoff is implemented; actual real-model generation and its acceptance evidence remain unperformed until the separate user authorization and live prerequisites are satisfied.

## Verification

Fake subprocess tests exercise production startup, split/malformed JSONL, successful JSON output, EOF/exit failure, scope/receipt/expiry checks, concurrent use, failed spawn, cancellation during metadata, immutable dispatch snapshots, independent authority mutations, ignored user MCP versus retained system MCP, requirement overrides and malformed layers. Existing Core integration tests cover static acceptance, exact retry, changed-work conflict, pending human review and unchanged canonical state. Fakes establish software behavior, not official billing or tool capabilities.

Separate non-inference official `0.160.0` probes accepted the exact controls, suppressed a malicious isolated project config, and passed the selected native environment/workspace safety preflight after stock-exec reconstruction. The same named profile denied a non-sensitive fixture read, cwd write, outside write and direct TCP connection with EPERM. These are metadata/source/OS evidence, with zero model calls; they do not establish real-model output, billing consumption or all-tool absence.
