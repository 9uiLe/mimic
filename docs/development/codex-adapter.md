# Official Codex adapter boundary

`apps/cli/src/agent/codex.ts` implements the 9UI-167 `AgentExecutor` contract for the unmodified official Codex CLI. Supply an absolute executable path, an existing workspace, and an explicit environment containing only the process helper's allowed native-login variables. It reads `--version` and `login status`; it never reads credentials, logs raw command output, starts login, grants permissions, invokes private HTTP endpoints, or selects another backend. This implementation recognizes official CLI version `0.160.0`; other versions require explicit compatibility verification.

## Subscription-only stop

The billing policy forbids API billing/fallback, new credit purchases, and unauthorized consumption of existing credits. Existing ChatGPT login alone does not verify those account settings or the generation profile. `describe()` therefore reports `entitlement.status: "unconfirmed"` with reason `billing` for a recognized runtime with ChatGPT login. `startExecution()` emits `billing-unconfirmed` with resume condition `verify-subscription-only`. Calling `CodexExecutor.start()` directly also stops before inference. Missing, unknown, and API-key authentication require official ChatGPT login; an unknown runtime is unsupported. Neither caller attestation, a model name, a quota snapshot alone, nor an API credential can unlock execution.

The official [personal-plan credit documentation](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-personal-plans) describes additional credit use. The [configuration reference](https://developers.openai.com/codex/config-reference) documents `forced_login_method = "chatgpt"`; that controls authentication rather than verifying the account's credit settings. A real smoke test requires official confirmation that additional-credit consumption/overage is disabled, or that credits are absent and auto-refill is off. Its generation profile must also force ChatGPT authentication and the built-in OpenAI provider, exclude API environment/endpoint overrides, check remaining quota, use Standard mode without auxiliary models, restrict tools, and apply a short timeout with no automatic retry. A third-party-app credit toggle is not proof of the stock CLI's setting.

A read-only inspection of the existing official CLI `0.160.0` using `account/read` with `refreshToken: false`, `account/rateLimits/read`, and `model/list` reported ChatGPT Pro authentication, 12% usage in the weekly quota window, and existing credits (`hasCredits: true`, `unlimited: false`). Seven visible model IDs were returned, with `gpt-6.1-sol` the default. These APIs did not expose an overage/additional-credit disable setting or auto-refill setting. No emails, account IDs, tokens or raw diagnostics were retained in the report. This is account metadata, not permission to consume credits or proof of a model invocation.

A real model smoke test is consequently **not performed**. The missing proof is the actual Codex account's additional-credit/overage setting; the adapter does not yet implement a trusted official account-control verification path or certify that all model tools are absent. A fixed generation profile and static submission handoff are implemented below, without dispatch authorization. The real generation and static-submit vertical slice remains incomplete. This is a concrete unverified account setting, not a demand for an absolute per-call spending guarantee. There is no production caller-attestation override. Future dispatch must use a trusted official metadata/control interface after the settings and generation profile are verified.

## Fixed invocation profile and static handoff

`createCodexGenerationProfile(options, request, outputSchemaPath)` prepares a fresh, ephemeral official `exec` invocation without launching it. The schema must be a regular workspace-contained file, including after realpath resolution. The profile fixes ChatGPT authentication, the built-in OpenAI provider, Standard (`service_tier = "default"`), read-only sandboxing, no approval escalation, and stdin input rather than shell interpolation. It ignores user config and rules, marks the workspace untrusted to suppress project config, disables the verified shell, plugin, app, hook, browser, image, memory, multi-agent and retry features, and limits the prompt, output and timeout. Callers cannot supply extra argv, change the tier/provider, or inherit ambient API keys, endpoint overrides, proxy variables, or Node injection variables. The process helper validates and copies an explicit native-login environment.

Every fixed key and feature was checked against the public official [0.160.0 configuration schema](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/config.schema.json). The schema documents `default` as a service tier. These controls are verified syntax and restrictions, not proof that every built-in tool is absent; the profile explicitly retains `toolRestriction: false`. Production `start()` still stops before inference. Changing a profile or supplying a fake entitlement does not unlock it.

`prepareCodexSubmission` checks the output envelope's Run/task identity, uses the CLI's ID syntax, rejects lexical path escapes and option injection, and returns serialized candidate JSON plus only `submit <run> --task <task> --package <package> --work <file> --root <workspace> --json` argv. It performs no filesystem writes. The outer session layer owns immutable saving/checkpoints; Core's static submit validates realpath containment, artifacts, digests, exact locks and immutable retry reservations. Approval and commit remain explicit human actions. No `CliHost.executeSkill` host is constructed.

## Protocol components

`CodexJsonlDecoder` consumes bounded stdout bytes incrementally using fatal UTF-8 decoding and the official versioned [exec event protocol](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/exec/src/exec_events.rs). It emits model output as candidate data, hides reasoning and raw diagnostics, normalizes quota/authentication failures, and rejects tool events, unknown events, malformed sequences and truncated output. A completed event is withheld until EOF and successful process exit. Process cancellation and timeout remain failures even if the stdout stream already contains `turn.completed`.

`executeOfficialProcess.onStdout` receives bytes only after the shared output-size bound. Callback failure terminates the process group and reports `unknown-outcome`. Chunks may split UTF-8 and JSON lines. The callback does not receive stderr, and mutating its copied buffer does not alter the collected result.

`parseCodexWorkEnvelope` checks only the `{ artifacts, work }` envelope shape. Future generation must send that candidate through the existing `mimic submit --package --work` static Skill path. Core still validates schemas, digests, origins, exact dependencies, immutable submission reservations, and revision requests. The parser does not approve or commit artifacts and does not replace `runSkillPackage` with `CliHost.executeSkill`.

The boundary advertises no native resume: ephemeral execution cannot persist an official session for later resumption. Mimic's outer checkpoint loop owns reconciliation and must not replace resume with a new turn that repeats accepted work. Tool restriction remains unconfirmed (`toolRestriction: false`). Streaming and structured-output protocol support do not imply permission to dispatch.

## Verification

`apps/cli/tests/agent-codex-contract.test.ts` uses explicitly fake CLI subprocesses and recorded protocol-shaped data. It covers read-only metadata, billing/authentication stops with no inference launch, API/endpoint rejection, split UTF-8 JSONL, failure classification, forbidden tool events, malformed work, nonzero exits, output bounds, callback failures, cancellation and timeout. They also drive an explicitly fake CLI through the fixed profile and use a decoded fixture through production `dispatchCli` static Skill submission. The fixture proves Core acceptance, exact retry, changed-work conflict, external-symlink rejection, pending human review and unchanged canonical state. It is not evidence of real model generation. Fresh ephemeral turns are distinct from native resume; Mimic checkpoint recovery must reuse accepted submissions rather than silently generate them again.
