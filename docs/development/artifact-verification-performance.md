# Artifact verification performance (9UI-153)

## Measured baseline

At `bcdcefc6cf3585f343644866f6dec6b180669fa2`, a valid 10-layer diamond of 21 exact artifact revisions and 38 incoming edges causes 2,047 recursive visits from one root. With pending approvals and `FileWorkspaceStorage`, one read performed 2,047 storage reads, 2,047 schema validations, and 2,047 full workspace loads (420.5 ms wall, 513.7 ms process CPU). A separate valid diamond with one CLI-created, committed local confirmation as a leaf performed 2,047 storage reads, 2,047 schema validations, 512 persisted confirmation checks, and 3,071 workspace loads (1,186.5 ms wall, 1,314.6 ms process CPU). Both measurements used Node 24.21.0 and Vitest 4.1.9 in an isolated temporary copy.

The 9UI-152 preserved synthetic Riverbend workspace contains 40 snapshots, 66 dependency edges, and 20 approved revisions in a 1,176,492-byte workspace file. Its instrumented incomplete-intent Portable retry ended in `Concurrent release claim` after 99.3 s, with 2,370 `ArtifactStore.read` calls and 7,134 workspace loads. A separate completed-workspace exact retry succeeded in about 68 s; its CPU profile concentrates in whole-workspace loading and canonical JSON. The incomplete-intent duration is not a successful publication duration. A fresh publication was then measured on a copy of the completed synthetic workspace after removing only the copied Portable package and claim records. With structural DAG deduplication alone it succeeded in 67,168 ms wall / 67,908 ms CPU, producing `sha256:816397f5d0e246c4cc533a389b7da6e2976aeefbe21717f74d4a85dbd5ca8daa`. The same fresh publication after the pinned internal registry evidence optimization succeeded in 2,545 ms wall / 2,786 ms CPU with the same digest. It made 119 top-level artifact reads, 868 node visits, 590 schema validations, 2,219 persisted local-confirmation checks, and 238 physical workspace reads (two per top-level read). No authority lifetime cache was introduced.

## Verification boundary

Each public top-level artifact read and each compile/publish freshness checkpoint needs a new verification context. All incoming edges must independently compare the exact child digest and scope. The context may reuse structural verification of a completed node only against one consistent workspace snapshot; it must detect cycles. Approval and provenance authority checks must be replayed on repeated paths, and callback failures remain fail closed. Within a workspace read session, internal verifiers use the frozen registry image; external authority callbacks receive copies of the matched decision and proposal. Session exit compares workspace source bytes and rejects a changed workspace. No verification result may persist across reads, approval, commit, or publication checkpoints. Mutable caller input and callback arguments remain isolated by copies.

## Options

| Approach                                                      | Cost and concurrency                                                                                                                                                                                                                                                                                                                                                                               | Decision                   |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| Per-read completed map alone                                  | Smallest artifact-store change, but a mutable workspace can change between node visits; repeated authority callbacks also reload the whole workspace.                                                                                                                                                                                                                                              | Insufficient alone.        |
| Consistent workspace read session plus per-read completed map | Bounded changes in artifact-store, workspace-transaction, registry publication verification, and local confirmation verification. One workspace image per read, with a final freshness check; node structure is checked once, every edge remains checked, and authority is replayed. Other storage implementations retain uncached verification unless they provide the same consistency contract. | Chosen for implementation. |

The session is a read consistency unit, not a store-lifetime or prepare-to-publish authorization cache. Publication retains its separate pre-approval, post-approval, and pre-rename checks.
