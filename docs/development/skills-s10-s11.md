# S10–S11 structural direction packages

S10 takes exact Problem Profile, Product UI Contract and Reference Selection locks. Its default portfolio contains four to seven candidate `design-direction` artifacts. It compares navigation, information architecture, interaction, spatial organization, density and temporal behavior pairwise; two or more structural differences distinguish each counted pair. Surface-only changes do not add a direction. Redundant options are merged or regenerated with a recorded disposition. A constraint relaxation experiment records the removed constraint, discovery goal and result against the original contract. Mechanisms can combine principles from multiple reference spaces, with do-not-borrow limits and failure modes. A proposed capability permits explicitly mock, provisional exploration when the task remains safe; it is never described as current support.

S11 takes all compared candidate locks plus the profile and contract. It derives criteria from actual task, goal, brand, contract and risk inputs that are available. Each `evaluation` targets one direction and records criterion source through narrow provenance with exact input locks. Empirical outcomes lacking relevant evidence remain `UNVERIFIED`. A `decision` may propose recommendation, alternative, hybrid or return to divergence; the owner must adopt a direction at the Human Commit Point. No aggregate numeric score or automatic selection is produced. A controlling brief may exclude a dimension from this design comparison; the evaluator then omits it rather than turning it into an `N/A` or `UNVERIFIED` gate. The source contract remains intact, and no compliance claim follows from the omission.

Both packages use the existing artifact schemas. The six-axis ledger, relaxation account, transfer limits, criterion-source details and rejected revision history live in narrow provenance or linked evidence because no dedicated v1 fields exist. The Orchestrator verifies exact dependencies and authority separately from schema shape. Every output is provisional or proposed with pending approval; a wholly blocked invocation returns zero artifacts.

`packages/core/src/skill-catalog-tests/s10-s11.test.ts` loads both manifests through `loadSkillPackage`, exercises the Orchestrator and shared workspace with exact locks, and consumes every declared scenario. It checks independently represented structural and visual variants, changed inputs, criterion sources, failing candidate convergence, human rejection followed by a new revision, pending decisions, and durable-output rejection with unchanged registry state. These deterministic checks establish package and runtime contract behavior only; they do not measure a model's creative quality, real user performance or empirical design truth.

For a same-Run S10 → S11 route whose direction digests are unknown when the plan is saved, the S11 `design-direction` input may set `refsFromTask` to the S10 task ID and list that task in `dependsOn`. After S10 completes, the Orchestrator binds all matching exact output refs from its verified completion event. The source must be a declared dependency with the matching output type; fixed `refs` and `refsFromTask` cannot be combined. The selector never reads a floating latest revision or mutates the saved task plan. Rejected, stale, foreign, and incomplete outputs remain unavailable.

The authorized Codex harness supplies `schemas/agent/codex-submission-output.schema.json` as its strict output schema. The single `submissionJson` string contains the serialized `{artifacts,work}` packet; Mimic parses that packet and applies the unchanged static submit validation. This wrapper accommodates varying artifact content while meeting the official Structured Outputs object requirements. A generated result must provide exact Run/task/Skill/input identities and one output reference per emitted artifact; only fresh output digests may use `host-derived`.
