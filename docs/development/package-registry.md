# Package registry and design lock

The package registry module is `packages/core/src/package-registry/index.ts` and is re-exported from `@mimic/core` through `packages/core/src/index.ts`.

`PackageRegistry` depends on `PackageSource`, `PackageAuthority`, an explicit scope tree, supported schema versions, and a license policy. It does not choose a release version or publish bytes. `FilePackageSource` reads exact releases from `<root>/<package ID segments>/<MAJOR.MINOR.PATCH>/`. The root may be a normal filesystem directory or a Git checkout. Another source can implement the same interface without changing package references or locks. The backing directory and verifier are trusted infrastructure; the digest detects mismatches against a separately supplied expected digest, not a malicious replacement of both bytes and that digest.

Each release directory contains `manifest.json`, `design.lock.yaml`, and the files named by the manifest. `design.lock.yaml` uses the JSON subset of YAML 1.2, serialized as indented JSON with a final newline. Parsing requires that exact representation so duplicate keys, aliases, tags, and ambiguous YAML scalar rules cannot enter a lock. The release manifest also uses this representation. Both documents have `format: 1`. A manifest names its package ID and exact `MAJOR.MINOR.PATCH` version, kind, distribution mode, scope, schema version, human approval reference, file inventory, assets, artifact revisions, and direct dependency edges. The lock names the root and every transitive package with its exact version, digest, acquisition hint, license, distribution, scope, schema version, asset and artifact inventory, and direct edges. The root's own asset and artifact entries are repeated in the lock for consistency checking. Artifact `revision` is a positive integer and is never interpreted as package or asset SemVer. Each artifact entry carries both `digest` for raw file bytes and `snapshotDigest` for the parsed artifact under `mimic-json-v1`.

`packageDigest` uses the distinct `mimic-package-bytes-v1` rule. It SHA-256 hashes the UTF-8 prefix `mimic-package-bytes-v1` followed by a zero byte, then lexically sorted frames for `manifest.json`, `design.lock.yaml`, every manifest-listed file, and every recursively bundled dependency file. A frame contains an unsigned 64-bit big-endian path byte length, UTF-8 path bytes, an unsigned 64-bit big-endian content length, and the exact content bytes. Bundled paths begin `bundled/<percent-encoded package ID>@<version>/`. File bytes, JSON whitespace, manifest fields, lock fields, and bundled dependency bytes therefore affect the package digest. This rule does not use the artifact store's `mimic-json-v1` rule. Each listed file also carries a SHA-256 digest over its raw bytes; artifact snapshot digests remain governed by the artifact store contract.

`resolve(rootRef, expectedDigest)` fetches the exact root release and checks its package digest, manifest, lock, approval, all listed files, schema versions, scope ancestry, license policy, direct edges, transitive closure, and nested locks. A resolved graph selects at most one version per package ID. For each included artifact, the caller must supply `artifactSchemas`; resolution parses the artifact, verifies its exact ID, integer revision, declared schema version, raw file digest, snapshot digest, scope, and schema. It also requires every artifact dependency to be present in the acquired graph at its exact ID, integer revision, and `lockDigest`, with permitted scope ancestry. Conflicting bytes for one artifact ID and revision, or an artifact dependency cycle, fail closed. No artifact entry can be verified without the schema registry. It never falls back to `latest` or a range. Missing bytes, changed bytes, incompatible schemas, out-of-scope dependencies, prohibited licenses, conflicting graph entries, and unavailable approval authority fail closed. `reconstruct` returns verified manifests and copied bytes for offline use. `resolveAsset` selects package ID, package version, asset ID, and exact asset version; `resolveArtifact` selects package ID, package version, artifact ID, and integer revision. An external dependency may be acquired from a local cache through any `PackageSource`; the lock's `source` is an acquisition hint, not identity or integrity authority. The registry copies scope configuration at construction and passes a copy of each verified manifest to the release-authority callback so those inputs cannot rewrite the validated result.

For a Portable Snapshot, every dependency edge throughout its transitive graph must be `bundled`, with its bytes under `bundled/<percent-encoded package ID>@<version>/` using the same directory structure recursively. This remains true when a bundled child is itself a Reference Package or when a Portable Snapshot appears below a Reference Package. A package reached through both portable and reference paths must satisfy the portable path. Resolution reads those bytes from each parent snapshot and rejects missing or unexpected bundled entries. A Reference Package outside a portable closure can use `external` edges and requires those exact bytes to have been acquired through the source. The resolver does not grant redistribution rights: the supplied license policy must permit each edge, and a portable release must carry the required bytes.

`recommendForNewProject` returns the highest verified, in-scope discovered version as a hint for a new project. It does not persist a selection or change any existing lock. `assessUpgrade` reports `NONE` for an unchanged exact version, `BREAKING` for a major-version change, and `REVIEW_REQUIRED` otherwise unless a caller supplies a reviewed `SAFE`, `REVIEW_REQUIRED`, or `BREAKING` classification. The report is not approval. A different version enters an existing product only through an explicit proposed change, review, validation, and human decision. `verifyPromotion` checks allowed scope steps and delegates human approval verification; it does not create an asset or release.

The module has no deletion, retention expiry, automatic release, Git commit, or mutable `latest` operation. Historical lookup is exact and returns `UNAVAILABLE` if bytes cannot be acquired. A later asset removal from discovery cannot rewrite an already released lock.
