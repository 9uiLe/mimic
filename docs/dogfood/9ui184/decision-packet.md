# 9UI-184: Mimic の参照方式を選ぶための判断資料

2026-10-10 06:05 UTC までに保存された実行証拠に基づく。ここで比べるのは**資料をいつ、どう提示するか**であり、S11 が提案した画面方向の正式採用ではない。目的は、利用者が根拠を理解し、納得できる設計・製品へ早く到達すること。モデル呼び出し回数だけでは方式を選ばない。

## 判断の要点

**新しい固定1 Run では、B0・C1・C2 の S09→S10→S11 が全て初回受理された。** 各方式が3つの構造案、3件の共通基準評価、暫定採否を保存した。三方式とも、現課題には共通基準を並べて比較し、個々の根拠を近くで調べられる構造を暫定推奨した。ただし、事例の役割づけ、代案、懸念には差がある。受理とモデルの提案は、利用者が画面を操作して納得した証拠ではない。

**暫定的には、既存の出典付き参照経路（B0 に近い運用）を維持し、C1/C2 を限定的に試すことを推奨する。** この1 Run では C1/C2 が B0 より良い案を生む、速い、安定すると示せない。C1 には課題に応じた host 検索と網羅漏れ確認、C2 には後段の反例確認という追加の仕事がある。選択するなら、下表の代償と未検証点を踏まえ、別 Run と実際の利用者判断で確かめる。正式な既定方式とデザイン方向の採用は、まだ人間が決めていない。

現行 localhost 画面の説明文は「**固定1 Run では B0/C1/C2 の S09–S11 が全件受理。方式の優劣・再現性・利用者の納得は未判定。**」が正確である。「比較未完」は今回の固定 Run には当てはまらない。ただし過去の停止履歴は残す。

## 今回の実測

「受理」は静的 CLI と Core が成果物を保存したという意味。各 arm の S09/S10/S11 は**それぞれ初回の1試行**で受理され、再生成は0回。下記の時間は3回のモデル生成に費やした合計で、準備、共通上流、順番待ち、利用者判断の時間は含まない。最初にレビュー可能になった時刻は逐次実行のため速度比較に使えない。

| 方式 | S09 の事例分類とカバー範囲                                                                                     | S10 の3つの構造方向                                                | S11 の暫定推奨と代案                                                        |   生成時間 |
| ---- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- | ---------: |
| B0   | GitHub Run を近接、SmartHR table を隣接、GOV.UK Details を遠い参照。preview の独立性や復帰経路などはカバー不足 | 共通基準マトリクス、質問順の導線、根拠関係インデックス             | マトリクス＋近接した根拠調査。質問順の導線を代案として残す                  | 403,429 ms |
| C1   | SmartHR table を近接、GitHub Run と GOV.UK Details を隣接。検索結果の役割は S09 が再評価                       | 根拠 drawer 付き基準マトリクス、誘導型チェックポイント、質問ドシエ | マトリクス＋文脈付き根拠 drawer。現在地と次の行動を優先するなら誘導型が代案 | 377,605 ms |
| C2   | teamLab object と SmartHR table を遠い参照、GitHub Run を近接。機構の移植条件を明示                            | オプション別ワークスペース、基準マトリクス、質問順シーケンス       | 基準マトリクス。安定した案を繰り返し見るならワークスペースが代案            | 446,864 ms |

S09 の「近接・隣接・遠い」は各出力の提案分類であり、参照元の客観的な順位ではない。C2 が teamLab と SmartHR を遠い参照にしたことも、C1 の host 検索が「正解」だった根拠にはならない。S10 の3案はそれぞれ情報の入口と調査の進み方が違い、色や装飾だけの変種ではない。一方、実画面として操作したわけではない。

三方式の S11 は、比較に必要な情報、隠れた決定情報と根拠、不要なノイズ、次の行動を中心に評価した。B0 はマトリクスの「現在地と次の行動」の指定不足と、質問順案の横断比較負荷を指摘。C1 はマトリクス密度と、誘導型の基準間移動負荷を比較。C2 は密度や離れた根拠パネルが次の行動を埋もれさせる危険を反例として明示し、オプション選択に意味がない場合はワークスペースが弱いとした。どの方式も、preview の実操作、根拠の実在関係、レビュー担当者の理解や満足度は未検証と扱った。アクセシビリティは今回のデザイン評価・収束の軸に含めていない。既存操作機能は維持する。

暫定採否の exact refs は B0 `art_run_9ui199_minimal_20261010_v10_s11_b0_direction_decision@1` (`sha256:4b7a5194930ecf2426878754c55bfee0dbf7e48601fc0b31252a1db2f4d3596d`)、C1 `art_run_9ui199_minimal_20261010_v10_s11_c1_direction_decision@1` (`sha256:af63b73a44496de8db0c0c70874698fa79197ed3ca046864df7242cdf7a4d2fe`)、C2 `art_run_9ui199_minimal_20261010_v10_s11_c2_direction_decision@1` (`sha256:c5281bd565cfd7ab9c8f85a43bbb6e740fe3f0b92105bdd4a46d8e6445587874`)。全評価・参照選択・方向案の exact refs は[機械レポート](../9ui183/accepted-fixed-comparison-9ui199-v10.json)にある。三件とも `outcome: proposed` で、人間採用はない。C2 の停止理由 `approval` も採用完了ではなく審査待ちである。

この比較は単一 Run、各方式1回であり、再現安定性や因果的な品質・速度差は測れない。モデル原文の手直しはせず、公式の認可経路と静的受理を使ったが、試行順効果と出力の偶然性は残る。実行レポートの時間は generation に限られ、準備・共通上流・審査・利用者の選択時間、費用は測っていない。正式な方式採用、S11 の画面方向採用、利用者の有効性・納得は未判断。S13 以降に必要な承認済み foundation もこの Run にはないため、画面品質をそこから推定しない。

## 人間が選ぶこと

当面、現行の出典付き参照経路を維持する案は、操作確認済みの画面と実行経路を保ち、課題条件付き検索や後段反例確認を必須処理へ増やさない。代わりに、出典付き事例から適合機構を選ぶ理由と不適用条件を S09/S11 で丁寧に示す必要がある。C1 を試すなら、host 検索が有用な遠い参照を落とさないかを別 Run で確認する。C2 を試すなら、後段反例確認が見落としを減らすか、手戻りを増やすかを観察する。

正式な既定方式を選ぶ前に、少なくとも別の課題・別 Run で再現し、利用者が同じ資料から推奨理由、代案、決定的な caveat、次の行動を説明できるかを観察する。今回の判断資料はその選択の入力であり、選択そのものではない。
