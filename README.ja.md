# Mimic

**デザイナーのように設計する。** [English](README.md)

Mimic は開発初期段階にある、特定のモデルに依存しない、AI が操作するプロダクトデザインエンジンです。人が操作役の AI エージェントと協働し、そのエージェントがローカル CLI、Skill、ファイルに保存されたアーティファクトを使ってデザインを探索します。目指す成果物は、人やツールが確認・批評・実装に利用できる、バージョン付きの **Design Package** です。Mimic は本番アプリの自動生成ツールでも、本番用フレームワークへの変換サービスでもありません。

## なぜ Mimic なのか

汎用的な AI への指示だけでは、ユーザーやタスク、制約が異なる製品でも、見慣れたレイアウトや視覚表現に収束しがちです。Mimic は問題と根拠から始め、タスクの特性、デザイン原則、転用できる仕組みを調べてから、操作の方向性や視覚表現を選びます。参照事例は分析する材料であり、画面を模倣するためのものではありません。これはプロジェクトの目標であり、現時点の Skill が実際のデザイン品質を改善すると実証されたという主張ではありません。

## デザインの流れ

目指す流れは、製品定義とユーザーのタスクから、ブランド、システム機能、共通の Product UI Contract、Experience Domain へ進みます。次にデザイン上の問題を整理し、参照事例と異なる方向性を探索し、デザインシステムを決め、プロトタイプを構成して批評・検証します。全体の順序は[デザインフロー](docs/specifications/design-space-exploration.md)と[Run の契約](docs/specifications/orchestrator-runs.md)を参照してください。

**System-first** は既存システムで根拠のある機能から、**Experience-first** は望ましいユーザー体験から始めます。どちらも同じ流れへの入口です。Product UI Contract で合流し、承認規則も共通です。提案中のシステム機能を実装済みとして扱うことはできません。

目指す運用サイクルは、確定済みの状態 → 巻き戻せる Run → 暫定アーティファクトと根拠 → **Human Commit Point** → 対象リビジョンの採用または破棄です。AI は代替案の探索、草案、プロトタイプ作成、チェックを自律的に進められます。製品定義、ブランド、Experience Domain の境界、採用する方向性、共有アセットへの昇格、最終リリースなどの永続的な選択は人が行います。操作役のホストは、正確な提案を人に提示して明示的な確認を得てから、決定やコミットを記録しなければなりません。判断待ちでも、独立した可逆的な作業は続けられます。

## Design Package の内容

目標とする Design Package は、機械可読なデザイン上の決定、デザインシステムの使用情報、セマンティックな HTML/CSS/JavaScript の実行可能なプロトタイプ、シナリオ、システム要件、検証の根拠、決定履歴をまとめます。承認済みアーティファクトとリリース済みパッケージは、バージョン管理し、その場で書き換えない設計です。目標の形式とライフサイクルは[パッケージ管理の仕様](docs/specifications/design-package-governance.md)を参照してください。リリース用バックエンドはまだ実装されていません。

## 使い始める

Node.js **24.21.0** と pnpm **12.9.1** を使用します。`pnpm install --frozen-lockfile` と `pnpm build` の後、リポジトリのルートからローカル CLI を実行します。

```sh
node apps/cli/dist/main.js skill
node apps/cli/dist/main.js skill flow --mode experience-first
node apps/cli/dist/main.js skill show s01 --full
```

`mimic skill` は操作役の AI 向けの読み取り専用の案内インターフェースで、ワークスペースの初期化前に使えます。導入済み Skill パッケージ、フロー、スキーマ、関連文書を探せます。Skill の実行やデザイン上の決定は行いません。最初のワークスペースの進め方は[オンボーディングガイド](docs/onboarding/README.md)、正確なコマンドと確認ファイルの形式は[CLI リファレンス](docs/development/cli.md)を参照してください。

## 現在の状態とアーキテクチャ

Mimic は **プレアルファ** です。リポジトリにはローカル CLI、Core のオーケストレーションとアーティファクト保存、スキーマ契約、静的な Skill パッケージ、デモラボがあります。`init`、`status`、`run`、`next`、`submit`、`decisions`、`decide`、`validate`、`skill` は、文書に記した制約の範囲で実装されています。`preview` と `release` のバックエンドは現時点で実装されていません。デモラボはローカルのプレビュー画面であり、Design Package のデプロイ経路ではありません。静的な Skill 定義と合成テストが確認するのは契約であり、AI による実際の推論や実証的なデザイン品質ではありません。

構成上の境界は **人 → 操作役の AI エージェント → ローカル CLI とファイルシステム → モデル非依存の Core** です。Orchestrator がファイルに保存されたアーティファクトを Skill 間で受け渡し、Skill 同士は直接呼び出しません。スキーマ検証、レジストリのチェック、人の承認は AI の推論とは別です。Core に MCP やホスト型バックエンドは必須ではありません。[オンボーディングガイド](docs/onboarding/README.md)では現時点の機能と目標のフローを区別し、[技術アーキテクチャ](docs/specifications/technical-baseline.md)では詳しい境界を説明しています。
