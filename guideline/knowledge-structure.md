# 知識の構造ガイド

`knowledge/` は、一つの概念・思想・哲学につき一つのディレクトリを用意します。各概念に固定の本文入口を置き、独立した `relations/` の意味付き関係グラフからも索引できる構成です。読む順序と範囲は、読む人やAIが目的に応じて決めます。ClaudeやCodexのスキルに似た資料の配置を用いますが、スキルとして呼び出したり実行したりするためのものではありません。

掲載する内容の判断は[Repositoryの方針と利用ガイド](README.md)に従います。知識の参照は[知識の索引](../knowledge/README.md)から始め、Repositoryの変更・点検では[AI向けの作業ガイド](ai.md)に従います。

## Repository全体の配置

| 場所 | 正本・責務 |
| --- | --- |
| `knowledge/` | 概念の説明と、その概念に属する出典対応表・例 |
| `relations/` | 全概念のノード、根拠付きの意味辺、関係型の語彙 |
| `topics/` | 目的・題目別の横断的な案内 |
| `guideline/` | 利用・編集・表示・開発・品質検査の方針 |
| `design/` | 閲覧UIのDesign Tokenと、疑問から知識を探す案内 |
| `scripts/` | 生成・検査。単体ローカルプレビュー用 `knowledge-view.css` も保持 |
| `web/` | Pages閲覧UIの共通CSSと、共通操作・関係探索のJavaScript |
| `assets/` | 配信するフォントとライセンス |
| `tests/`・`.quality/` | 検査と、検査条件・変更の根拠 |
| `.github/` | GitHub Actionsの検査・公開処理 |
| `output/`・`_site/` | Git管理外の下書き・作業出力、Pagesの生成物 |

概念のID・本文URLを保ち、関係の構造や表示の都合だけで本文と補足を移動しません。概念の説明を `relations/` や `web/` に複製せず、関係や表示の変更はそれぞれの正本に反映します。

## 閲覧UIの設計と知識の境界

[閲覧UIのデザインシステム](design-system.md)はMimicへの適用規則、`design/tokens.json`は設計値と参照、`design/reading-paths.json`は仕事中の疑問から知識へ案内する編集元です。7つの疑問は正式な概念分類や必読順序ではありません。これらを知識本文や意味付き関係の正本へ混ぜず、閲覧UIの都合で原題・本文・引用・関係の意味を変えません。

## 本文と独立した関係グラフ

`relations/graph.json` は全概念のノードと意味付きの辺、`relations/vocabulary.json` は関係型・方向・推移規則の正本です。[関係グラフの案内](../relations/README.md)にデータの読み方と更新上の境界を定めます。本文内の関係の説明は人向けの文脈であり、構造化した関係を別途定義する場所にはしません。

辺は本文の説明を根拠に分類し、対象範囲と確認箇所を持ちます。本文を分類へ合わせて定義し直さず、根拠がない階層・依存を埋めません。グラフには網羅性の保証がなく、未記載は無関係を意味しません。逆参照は元の辺の向きを保って読み、推移は語彙が認める型と範囲に限ります。AIの索引方法や読書順序をデータ構造から強制しません。

## 固定の入口と補足

```text
knowledge/
  README.md
  <概念ID>/
    KNOWLEDGE.md
    references/
      sources.md
    examples/       # 説明例が必要な場合
    scripts/        # 補助スクリプトが必要な場合
```

`knowledge/README.md` は概念を探す索引です。各ディレクトリの入口ファイル名は、大文字の `KNOWLEDGE.md` に固定します。ディレクトリ名は概念を表す英小文字とハイフンのIDとし、入口の `id` と一致させます。

`KNOWLEDGE.md` は、概念の定義、背景や提唱者の立場、対象範囲、関連概念との違いを説明する本文です。補足を読む目的が分かるリンクを置き、出典や説明例へ案内します。概念を理解するための中心的な説明を、補足へ分散させません。

`references/sources.md` は出典の対応表です。原典や公式資料のURL、確認する章や箇所、どの主張を支えるか、対象範囲や解釈上の注意を記載します。原典の内容と、このRepositoryによる整理を区別します。原典の複製を置くことを必須にはしません。

`examples/` は、説明に必要な例がある場合だけ作成します。作成した例か、出典の例かを明示し、何を説明する例であるかを記載します。例を効果の実証や普遍的な設計案として扱いません。本文と同じ説明を独立に複製せず、本文から参照します。

視覚的な理解を補助する説明図も `examples/` に置き、例のMarkdownから画像として表示します。
図の文章による説明、代替テキスト、図そのものへの通常のリンクを用意します。
AIが読む `KNOWLEDGE.md` からも、例と図を参照できるようにします。
現在の図は編集用と表示用を兼ねる自己完結のSVGで、Pagesの公開一覧に明示したものだけを配信します。
表示と生成の条件は[説明図と画像](knowledge-view.md#説明図と画像)に定めます。

`scripts/` は、概念の説明を補助する処理が必要な場合だけ作成します。用途、実行方法、入力と出力、必要な依存を記載します。入口を読んだことを実行の指示とは解釈せず、公開・送信・削除・費用発生・稼働中の環境変更を伴う操作は、方針に従って許可を確認します。Repository全体の生成・検査を行うスクリプトは、ルートの `scripts/` で管理します。

空の補足ディレクトリや、使わない雛形は作成しません。各概念に `references/sources.md` を用意し、必要に応じて説明例を置きます。補足資料への入口は各本文に示します。現在、知識を補助するスクリプトはありません。

## メタデータ

`KNOWLEDGE.md` の先頭に、次のメタデータを置きます。

| 項目 | 内容 |
| --- | --- |
| `id` | ディレクトリ名と一致する概念のID |
| `title` | 本文の題名 |
| `version` | 説明文の版 |
| `scope` | 説明する対象範囲 |

構造化した関係を本文のfrontmatterには持ちません。関係の定義元は `relations/` に一本化します。版の意味は運用方針に従います。参照先や説明例には入口から到達できるようにし、本文と食い違う説明を独立に持ちません。

このメタデータは知識を識別して参照するためのものです。スキルの起動名、起動条件、ツール許可、実行手順などの実行契約を定義するものではなく、`SKILL.md` は用いません。

## 一つの概念と横断的な案内

一つのディレクトリでは、その概念を中心に説明します。別の概念との関係が必要なときは、相手の `KNOWLEDGE.md` へリンクします。関連する内容をすべて同じ記事へ取り込んだり、複数の概念をまとめて一つの確立した理論として扱ったりしません。

複数の概念を横断して読むための案内は `topics/` に置きます。[「判断材料の選定」](../topics/decision-material-selection.md)は、情報内容や表現を考える際に関連する概念への道筋です。個別概念の本文や出典を複製せず、読む理由を添えて各入口へリンクします。案内を読んだだけでは、リンク先の概念を参照済みとは扱いません。

## 生成と公開

個別概念の本文や補足資料はMarkdownを正本として編集します。Pagesでは明示した概念の本文と出典・例のHTMLも生成し、元のMarkdownとともに配信します。一覧や本文から、対応する閲覧先へ進めます。

「判断材料の選定」の閲覧ページは、`topics/decision-material-selection.md` からPages用HTMLとして生成します。任意のローカルプレビューは `output/knowledge-preview/` に生成します。案内はリンク先の概念や補足資料を自動的に取り込んだ全文ではありません。

Pagesの公開対象は[公開ファイルの一覧](../scripts/build-pages.ts)に明示します。知識ディレクトリにファイルを置いたことだけでは、Pagesへの公開やスクリプトの実行は行いません。生成・検査・公開の操作は[開発・公開ガイド](development.md)を参照します。
