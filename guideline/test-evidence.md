# 仕様の根拠とテストの検出力

テストが通ることと、期待結果が正しいことを別々に確認します。新規・変更する処理には、入力、具体的な期待結果、根拠の所在、確定・仮定・現状の記録の区別を先に記載します。既存テストと実装の一致だけでは、正しい仕様と断定しません。

## 根拠を先に確かめる

期待結果は明示された要件、公開された契約、Repository内の方針やガイドなど、検査対象から独立した根拠で判断します。実装と既存テストしか根拠がない場合は `current-record`（現状の記録）とし、仕様の確定には使いません。業務上の判断が未確定なら `assumption`（仮定）とし、採否を未確定事項に残します。

実演ケースは[ケース定義](../.quality/behavior-cases.json)に置きます。`confirmed` は記載した要件の確認を表し、対象全体や知識の意味の正しさを表しません。根拠の引用と所在が存在するかは実行時に検査しますが、引用の解釈が妥当かはレビューします。

`knowledge-relative-link` は[開発・公開ガイドの生成の規則](development.md#生成の規則)にある、出力位置から同じ参照先へ届くという要件を扱います。テスト用の出力先 `/repo/prototypes/decision-material-selection` から `/repo/knowledge/grouping/KNOWLEDGE.md` へ届く期待値を、`../../knowledge/grouping/KNOWLEDGE.md` として固定しています。このパスは相対リンクの検査用例であり、現行の生成先を表しません。[知識の構造ガイド](knowledge-structure.md#固定の入口と補足)が定める入口への具体例です。

相対パスを求める対象処理を呼んで期待値を計算せず、期待値をテストへ直接記載します。説明用パスは実在を必要とせず、macOS/Linuxのパスを使います。このケースは知識本文の内容、採用判断、Windowsへの対応を保証しません。

## 同じテストで誤りを検出する

Repositoryのルートで実行します。依存の自動導入は行いません。

```sh
bun test ./tests/knowledge-paths.test.ts
bun scripts/quality/verify-behavior.ts --case knowledge-relative-link
```

専用コマンドは、登録したソース・テスト・補助ファイルだけを一時ディレクトリへ複製します。同じテストの内容をSHA-256で固定して、次の順序で実行します。

1. 正常な実装で成功する。
2. 相対パスの起点と参照先を逆転する誤実装で、同一参照先のアサーションが失敗する。
3. コピー内の実装を復元し、再び成功する。

誤りの検出として認めるのは、登録されたテスト名とアサーションによる失敗です。構文エラー、読込失敗、タイムアウト、中断、未実行は成功扱いしません。元の作業ファイルには誤実装を書き込みません。一時ディレクトリは終了時に削除し、元のソースとテストが不変であることを確認します。

結果はGit管理対象外の `output/quality/behavior-proof.json` へ出力します。入力・期待値・根拠・実装とテストのSHA-256・各段階の終了コード・実際のアサーションと出力を含みます。別の出力先が必要なら `--report output/quality/別名.json` を指定します。成功の出力だけを転記せず、対象の根拠と失敗したアサーションを別々に報告します。

## 新規・変更する処理で続ける

振る舞いに関係する差分をレビューするときは、対応する根拠とテストの保証責任を確認します。新規・変更したテストについて、要件に関係する計算や条件分岐の誤りを同じテストで検出する証拠を用意します。代表ケース一件の成功を、すべてのテストの検出力の確認へ拡大しません。

再実行可能なケースは `.quality/behavior-cases.json` の `cases` に追加します。処理の識別子、入力・期待値、根拠・状態、仮定、実装・テストのパス、テスト名、補助ファイル、意図的な誤変更と対象アサーションを記載します。`find` は実装へ一回だけ一致し、`replace` は要件に関係する誤りを作る内容にします。テストは登録したファイルだけで実行できるようにし、必要な自作の依存は `supportingFiles` に明記します。

```sh
bun scripts/quality/verify-behavior.ts --case <登録したID>
bun scripts/quality/verify-behavior.ts
```

最後のコマンドは全登録ケースを検証します。登録のないテストや仕様の網羅性、命名や説明の意味の適切さは、自動で認定しません。レビューでは変更対象ごとの対応漏れと未確定事項を確認します。

合格のためだけに期待値を実出力へ合わせる、アサーションを弱める、`skip` や対象除外を追加する操作は行いません。仕様変更やテストの誤りを独立した根拠で確認できた場合は、その根拠と期待値・検証内容の差分をレビュー対象として示します。検査基準、除外、既存違反の記録、hookやCIの条件も、変更理由と影響を別に確認します。
