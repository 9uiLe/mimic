# 知識を読むページの表示規約

Pagesの共通枠の表示方式は`mimic-pages-reader` `1.0.0`、単体ローカルプレビューの表示方式は`mimic-knowledge-view` `3.4.1`です。各概念の正本は `knowledge/<id>/KNOWLEDGE.md`、題目別案内の正本は `topics/` のMarkdownです。Pages用に指定した本文・出典・例のHTMLを生成し、Markdown原文も保持します。

## 読者ができるようにすること

知識の定義、関連する概念との違い、説明の対象範囲、出典を、本文の構成に沿って読めるようにします。版を示します。HTMLの生成検査は、配信する文章とリンクの検査です。知識の正しさや使いやすさを実証するものではありません。

## 通常の知識本文

通常のMarkdownでは、H2の章立てと順序をそのまま表示し、同じ見出しを目次に使います。知識の説明に、判断手順・成果物・未検証事項などの区分を追加することはありません。H1はメタデータの題名と一致する一つに限り、本文はH2から始めます。各章には本文を置きます。

H2と小見出しのリンクIDは、見出しの文字から生成します。英字は小文字にし、記号を除き、空白をハイフンにします。同じIDには連番を付けます。見出しの変更時は、章へのリンクが変わる場合があります。目次とページ内リンクは同じ生成で更新します。

## 役割を指定するMarkdownの表示

章直前に `<!-- mimic:section purpose -->` などのコメントを置く形式では、以下の8役割をすべて必須とし、役割に対応する表示順と目次を使います。これは生成器が扱う形式の契約であり、通常の知識本文にこの形式を強制しません。

| 役割ID | 表示する内容・順番 |
| --- | --- |
| `purpose` | 目的と使う場面 |
| `inputs` | 使う前に確かめること |
| `procedure` | 判断の進め方 |
| `outputs` | 判断案と選定理由 |
| `related` | 他の知識との関係 |
| `example` | 例で確かめる |
| `sources` | 根拠といえる範囲 |
| `unverified` | まだ確かめていないこと |

この形式の小見出しには `<!-- mimic:heading axis-purpose -->` のように安定IDを指定します。一段落の注記には `<!-- mimic:note proposal -->` を使い、種別は `proposal`・`assumption`・`limitation`・`evidence-scope` です。未知の役割、重複ID、未定義の注記、不完全な構成は生成を止めます。コメントへ本文を重複して書きません。

## 共通の表示と部品

ページ上部の題名・版、一覧と原文への参照先、開閉できる目次、見出し・本文・注記・表の見た目、配色、余白、狭い画面での配置を共通化します。内容を更新するたびに配色や配置を作り直しません。本文や章が増えれば、ページの長さも変わります。
文字の拡大などで横幅が足りない場合、上部のブランド名と案内リンクを改行して画面内に収めます。

- 知識の一覧では、名称と説明を本文列、版を右の補助列に配置します。狭幅でも版を名称・説明の列へ混ぜず、本文列を折り返します。
- 説明は見出しと本文で読み進め、すべてをカード化しません。題名の近くに版を置き、識別IDや指紋は生成情報へまとめます。
- 本文の読書幅と補助列を分け、狭幅では一列へ組み替えます。目次は初期HTMLでは閉じ、広幅の初回読込時だけ開きます。利用者の開閉はリサイズで変えません。JavaScriptなしでも目次を開閉できます。
- 出典・例は対応する本文へ戻るリンクと原文へのリンクを持ちます。
- 通常の番号付きリストは通常のリストとして表示します。8役割形式の `procedure` 内の番号付きリストだけを手順部品にします。
- 表は狭い画面で横へ読める領域にします。
- 8役割形式の注記は関係する段落に置き、色に加えて種別名を表示します。本文の太字や位置から注記の意味を推測しません。
- 編集元のMarkdownと利用ガイドへの参照先を示します。
- 共通ナビゲーションから入口と関係探索へ進めます。本文・出典・例・関係のリンクは、選んだ知識のIDと元の疑問をURLで引き継ぎます。直接URLからでも本文と明示した戻り先をたどれます。

## 編集元と生成

題目別案内は `topics/` のMarkdown、概念の本文は `knowledge/<id>/KNOWLEDGE.md` を編集元にします。Pagesは正本から `topics/decision-material-selection.html` と `topics/product-ui-design.html` と `topics/scenario-to-screen.html` を生成し、一覧と関連概念からの閲覧先にします。任意のローカルプレビューは `output/knowledge-preview/` に生成し、Git管理しません。人用・AI用の文章を独立して管理せず、生成物を直接編集しません。表示構造と生成規則は[生成器](../scripts/build-knowledge.ts)、Pagesの共通枠は`scripts/pages-design.ts`、書体・色・余白・画面幅への対応は`web/reading.css`、共通操作は`web/reading.js`が実装です。単体ローカルプレビューのCSSは`scripts/knowledge-view.css`に保持します。

単体ローカルプレビュー用CSSはHTMLへ埋め込み、`url()`や`@import`を含めません。Pagesでは`web/reading.css`とTokenから変換したCSSを結合してHTMLへ埋め込みます。同じToken CSSを`web/tokens.css`としても配信します。PagesのHTMLだけは、同じPages成果物に同梱したGen Interface JP 0.8.0の400・600ウェイト別CSSを読み、必要なWOFF2サブセットを同一オリジンから取得します。任意の単体ローカルプレビューはフォント資産へのリンクを出さず、代替書体で読めます。本文へのHTMLや外部画像の埋め込みは許可せず、HTTP・HTTPS以外の外部リンクを拒否します。説明図は次節の明示したSVGに限って画像として表示します。知識の版と表示方式の版を分け、原文・共通CSS・生成器の指紋をHTMLへ記録します。Pagesでは共通枠のID・版と指紋も追加し、元のMarkdown生成器の生成情報を保持します。

ローカルプレビューで生成する `ai.md` は編集元の本文とメタデータを保持し、相対リンクだけを出力位置に合わせて補正します。リンク先の概念・出典・例の本文は取り込みません。Pagesは各正本のMarkdownを直接配信します。

段落・見出し・表にあるインライン形式の相対リンクに対応し、コード中は補正しません。参照形式の定義や、リスト内の相対リンクなど、内容と参照先を正確に保持できない構文は生成を止めます。IDは小文字英数とハイフンで表し、`KNOWLEDGE.md` を生成するときは親ディレクトリのIDと一致させます。本文メタデータは `id`・`title`・`version`・`scope` を保持し、構造化した関係は `relations/` を参照します。

補足は必要に応じて `references/`、`examples/`、`scripts/` に置きます。ディレクトリがあることを、内容の自動取り込み、スクリプトの実行、公開の指示として扱いません。GitHub Pagesは指定した本文・補足だけを配信し、旧 `knowledge/*.md` の公開URLには新しい参照先への移動案内を生成します。移動案内は知識本文の正本ではありません。

## 説明図と画像

説明に必要な図は、対応する概念の `examples/` に自己完結のSVGとして置きます。
公開一覧で明示した図だけを、Markdownの `![代替テキスト](相対パス)` から画像として表示します。
図の全体を見られる通常のリンクと、図が説明する関係を文章でも添えます。
画像内の文字だけに定義や重要な区別を任せません。

PagesではSVGをそのまま同梱し、HTMLの画像は読書幅に収まる比率で表示します。
生のSVGをHTMLへ挿入せず、画像要素から参照します。
外部参照・スクリプト・HTMLを含むSVG、一覧外の図、外部画像は受け付けません。
必要な図が欠けている場合や図の形式が不正な場合は、既存の出力を書き換える前に生成を止めます。

AIが読む正本Markdownにも、同じ図への相対リンクと文章による説明を置きます。
ローカルプレビューの生成Markdownでは、通常のリンクとインライン画像の参照を同じ図へ届くよう補正します。
出典の図とMimicが作成した説明図を区別し、作例を設計効果の実証として扱いません。

## 確認する範囲

生成検査では、人向けHTMLに編集元の全内容があること、ローカルプレビューの生成Markdownが同じ内容・メタデータ・参照先を保持すること、通常本文の章順、8役割形式の構造、単体プレビューが外部資産を必要としないことを確認します。各概念の固定入口、IDとディレクトリの一致、関係データからの本文参照と補足へのリンクも検査します。Pagesの検査では許可したファイルだけを配信し、フォントのCSS・WOFF2・ライセンスが固定版と一致して同一オリジンから参照されること、リンクが公開範囲内で解決すること、旧URLの移動案内、補助スクリプトを実行・配信しないことを確かめます。

GitHub Pagesの入口は仕事中の疑問から知識を探す案内と全25件の知識の一覧です。疑問の候補は扱う観点・読む理由・根拠節を示します。知識名・索引の説明・本文の版を対応させ、各本文のHTMLへ進めます。題目別案内は別の読書経路として残します。生成検査の成功を、出典の正しさや知識の妥当性の判断として扱いません。

## Pagesの読書経路

一覧の説明は `knowledge/README.md` の表から読み、題名・版は各本文から読みます。
疑問の案内は`design/reading-paths.json`から読み、候補のIDと本文の根拠節を対応させます。7つの疑問は概念の正式分類や必読順序ではありません。
一覧の対象は明示した25概念と照合し、ファイルを追加しただけでは掲載しません。
`scripts/pages-catalog.ts` は、配信する概念・補足とMarkdownからHTMLへの参照対応を明示します。
本文を一つのページへ取り込まず、概念・関連概念・例・出典をそれぞれのページで読みます。題目別案内も専用HTMLから、それぞれに関連する概念のHTMLへ進めます。「判断材料の選定」は7概念へ案内します。
正本のMarkdownをコピーしたファイルでは、原文と同じバイト列を保ちます。
旧題目別案内の人向けURLには短い移動案内を生成します。

## 関係グラフの表示

`graph/index.html` は `relations/graph.json` と `relations/vocabulary.json` から生成します。意味付き関係の定義元はこのJSONであり、表示用の独立した辺リストは管理しません。型・方向・推移の意味は[関係データの案内](../relations/README.md)と語彙を参照します。

選んだ知識の名称と本文リンクを先に示し、その知識につながる関係を読みます。関係ごとに型・方向・説明・対象範囲・根拠の引用と本文の確認箇所を表示します。名前から知識を選び直せます。配置の上下や距離から、未定義の階層・重要度・依存を推測させず、色や位置だけに意味を委ねません。

選択はURLの`concept`、元の疑問は`from`で保持します。ブラウザの戻る・進むでもURLに対応した知識を選び、未知のID、読込失敗、関係の未登録を区別します。未登録は無関係を意味しません。元の疑問は本文・出典・例を経由しても入口への経路へ引き継ぎます。

ブラウザ用の操作と表示は`web/`で管理し、共通CSSとTokenを使います。初期状態は静的一覧とし、選択表示はデータの読込・初期描画が成功してから表示します。スクリプトが届かない場合も静的一覧を読めます。JSONの解析などに失敗した場合は選択表示を隠し、短い利用不可の案内と静的一覧を示します。JavaScriptを使わない場合も、生成した静的一覧から知識・関係・根拠と本文へのリンクを読めます。操作用の表示と静的一覧は同じ関係データから生成し、本文を取り込んだ別の説明正本を作りません。生のJSONと関係データの案内へもリンクします。

Pagesの入口から一覧と関係探索へ、本文から該当する知識の関係へ進めます。関係を読んだことは、リンク先の本文や原典を確認したことにはなりません。読む順序と範囲は読者が決めます。

## スタイルと適用規則

色・Typography・余白・読書幅・部品・状態と例外は[閲覧UIのデザインシステム](design-system.md)を参照します。値とaliasは`design/tokens.json`、変換は`scripts/design-tokens.ts`を正本とし、共通CSSへ生成した変数を渡します。文字の五要素、書体と代替書体、light・不透明の色の組合せ、狭幅と文字設定変更の条件をまとめて管理します。

白地と黒い文字を基礎にし、全リンクの文字は通常・visited・hover・active・focusで黒を保ちます。開いた疑問の背景も白とし、青はfocus輪郭へ使います。状態や操作を色だけで伝えず、下線、輪郭、記号、内容の表示を組み合わせます。値だけで読みやすさやアクセシビリティを保証しません。
