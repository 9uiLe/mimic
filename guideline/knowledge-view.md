# 知識を読むページの表示規約

表示方式 `mimic-knowledge-view` の版は `3.3.0` です。各概念の正本は `knowledge/<id>/KNOWLEDGE.md`、題目別案内の正本は `topics/` のMarkdownです。Pages用に指定した本文・出典・例のHTMLを生成し、Markdown原文も保持します。

## 読者ができるようにすること

知識の定義、関連する概念との違い、説明の対象範囲、出典を、本文の構成に沿って読めるようにします。版を示します。HTMLの生成検査は、配信する文章とリンクの検査です。知識の正しさや使いやすさを実証するものではありません。

## 通常の知識本文

通常のMarkdownでは、H2の章立てと順序をそのまま表示し、同じ見出しを目次に使います。知識の説明に、判断手順・成果物・未検証事項などの区分を追加することはありません。H1はメタデータの題名と一致する一つに限り、本文はH2から始めます。各章には本文を置きます。

H2と小見出しのリンクIDは、見出しの文字から生成します。英字は小文字にし、記号を除き、空白をハイフンにします。同じIDには連番を付けます。見出しの変更時は、章へのリンクが変わる場合があります。目次とページ内リンクは同じ生成で更新します。

## 役割を指定するMarkdownの表示

章直前に `<!-- mimic:section purpose -->` などのコメントを置く形式では、以下の8役割をすべて必須とし、役割に対応する表示順と目次を使います。これは生成器が扱う形式の契約であり、通常の知識本文にこの形式を強制しません。

| 役割ID | 表示する内容・順番 |
| --- | --- |
| `purpose` | 目的と使う場面 |
| `inputs` | 使う前に確かめること |
| `procedure` | 判断の進め方 |
| `outputs` | 判断案と選定理由 |
| `related` | 他の知識との関係 |
| `example` | 例で確かめる |
| `sources` | 根拠といえる範囲 |
| `unverified` | まだ確かめていないこと |

この形式の小見出しには `<!-- mimic:heading axis-purpose -->` のように安定IDを指定します。一段落の注記には `<!-- mimic:note proposal -->` を使い、種別は `proposal`・`assumption`・`limitation`・`evidence-scope` です。未知の役割、重複ID、未定義の注記、不完全な構成は生成を止めます。コメントへ本文を重複して書きません。

## 共通の表示と部品

ページ上部の題名・版、一覧と原文への参照先、開閉できる目次、見出し・本文・注記・表の見た目、配色、余白、狭い画面での配置を共通化します。内容を更新するたびに配色や配置を作り直しません。本文や章が増えれば、ページの長さも変わります。

- 説明は見出しと本文で読み進め、すべてをカード化しません。題名の下に版を置き、識別IDや指紋は生成情報へまとめます。
- 一つの読書幅で本文を表示し、目次は必要時に開けます。狭い画面で目次の全項目が本文開始を押し下げないようにします。
- 出典・例は対応する本文へ戻るリンクと原文へのリンクを持ちます。
- 通常の番号付きリストは通常のリストとして表示します。8役割形式の `procedure` 内の番号付きリストだけを手順部品にします。
- 表は狭い画面で横へ読める領域にします。
- 8役割形式の注記は関係する段落に置き、色に加えて種別名を表示します。本文の太字や位置から注記の意味を推測しません。
- 編集元のMarkdownと利用ガイドへの参照先を示します。

## 編集元と生成

題目別案内は `topics/decision-material-selection.md`、概念の本文は `knowledge/<id>/KNOWLEDGE.md` を編集元にします。Pagesは正本から `topics/decision-material-selection.html` を生成し、一覧と関連概念からの閲覧先にします。任意のローカルプレビューは `output/knowledge-preview/` に生成し、Git管理しません。人用・AI用の文章を独立して管理せず、生成物を直接編集しません。表示構造と生成規則は[生成器](../scripts/build-knowledge.ts)、書体・色・余白・画面幅への対応は[共通CSS](../scripts/knowledge-view.css)が実装です。

共通CSSはHTMLへ埋め込み、`url()`や`@import`を含めません。PagesのHTMLだけは、同じPages成果物に同梱したGen Interface JP 0.8.0の400・600ウェイト別CSSを読み、必要なWOFF2サブセットを同一オリジンから取得します。任意の単体ローカルプレビューはフォント資産へのリンクを出さず、代替書体で読めます。本文へのHTMLや外部画像の埋め込みは許可せず、HTTP・HTTPS以外の外部リンクを拒否します。説明図は次節の明示したSVGに限って画像として表示します。知識の版と表示方式の版を分け、原文・共通CSS・生成器の指紋をHTMLへ記録します。

ローカルプレビューで生成する `ai.md` は編集元の本文とメタデータを保持し、相対リンクだけを出力位置に合わせて補正します。リンク先の概念・出典・例の本文は取り込みません。Pagesは各正本のMarkdownを直接配信します。

段落・見出し・表にあるインライン形式の相対リンクに対応し、コード中は補正しません。参照形式の定義や、リスト内の相対リンクなど、内容と参照先を正確に保持できない構文は生成を止めます。IDは小文字英数とハイフンで表し、`KNOWLEDGE.md` を生成するときは親ディレクトリのIDと一致させます。関連概念がない場合は `related:` を空にできます。

補足は必要に応じて `references/`、`examples/`、`scripts/` に置きます。ディレクトリがあることを、内容の自動取り込み、スクリプトの実行、公開の指示として扱いません。GitHub Pagesは指定した本文・補足だけを配信し、旧 `knowledge/*.md` の公開URLには新しい参照先への移動案内を生成します。移動案内は知識本文の正本ではありません。

## 説明図と画像

説明に必要な図は、対応する概念の `examples/` に自己完結のSVGとして置きます。
公開一覧で明示した図だけを、Markdownの `![代替テキスト](相対パス)` から画像として表示します。
図の全体を見られる通常のリンクと、図が説明する関係を文章でも添えます。
画像内の文字だけに定義や重要な区別を任せません。

PagesではSVGをそのまま同梱し、HTMLの画像は読書幅に収まる比率で表示します。
生のSVGをHTMLへ挿入せず、画像要素から参照します。
外部参照・スクリプト・HTMLを含むSVG、一覧外の図、外部画像は受け付けません。
必要な図が欠けている場合や図の形式が不正な場合は、既存の出力を書き換える前に生成を止めます。

AIが読む正本Markdownにも、同じ図への相対リンクと文章による説明を置きます。
ローカルプレビューの生成Markdownでは、通常のリンクとインライン画像の参照を同じ図へ届くよう補正します。
出典の図とMimicが作成した説明図を区別し、作例を設計効果の実証として扱いません。

## 確認する範囲

生成検査では、人向けHTMLに編集元の全内容があること、ローカルプレビューの生成Markdownが同じ内容・メタデータ・参照先を保持すること、通常本文の章順、8役割形式の構造、単体プレビューが外部資産を必要としないことを確認します。各概念の固定入口、IDとディレクトリの一致、関連概念と補足へのリンクも検査します。Pagesの検査では許可したファイルだけを配信し、フォントのCSS・WOFF2・ライセンスが固定版と一致して同一オリジンから参照されること、リンクが公開範囲内で解決すること、旧URLの移動案内、補助スクリプトを実行・配信しないことを確かめます。

GitHub Pagesの入口は全14概念の一覧です。概念名・索引の説明・本文の版を対応させ、各本文のHTMLへ進めます。題目別案内は別の読書経路として残します。生成検査の成功を、出典の正しさや知識の妥当性の判断として扱いません。

## Pagesの読書経路

一覧の説明は `knowledge/README.md` の表から読み、題名・版は各本文から読みます。
一覧の対象は明示した14概念と照合し、ファイルを追加しただけでは掲載しません。
`scripts/pages-catalog.ts` は、配信する概念・補足とMarkdownからHTMLへの参照対応を明示します。
本文を一つのページへ取り込まず、概念・関連概念・例・出典をそれぞれのページで読みます。題目別案内も専用HTMLから関連する5概念のHTMLへ進めます。
正本のMarkdownをコピーしたファイルでは、原文と同じバイト列を保ちます。
旧題目別案内の人向けURLには短い移動案内を生成します。

## 表示色の役割と条件

以下はMimicの閲覧ページのCSSに実装した役割名です。DTCG交換形式への準拠を意味しません。
基礎値を `--palette-*`、用途を `--color-*` として分け、CSSの参照で結びます。
lightのみ、全てsRGBの不透明な単色（alpha・要素opacityとも1）です。
文字色はcanvas・subtle・noteの各面、リンクはnormalとhover、focusは輪郭と隣接面で確認します。

| 役割Token | 参照するpalette | 値 | 用途・組み合わせる背景／状態 |
| --- | --- | --- | --- |
| `--color-surface-canvas` | `--palette-neutral-0` | `#ffffff` | ページ・本文・表の背景 |
| `--color-surface-subtle` | `--palette-neutral-50` | `#f6f7f5` | 表見出し・コード・研究資料の注記の背景 |
| `--color-text-primary` | `--palette-neutral-900` | `#243630` | canvas・subtle・note上の本文、通常 |
| `--color-text-secondary` | `--palette-neutral-600` | `#536258` | 同上の補足・版・状態・生成情報、通常 |
| `--color-link` | `--palette-green-800` | `#285e4d` | 同上のリンク、通常。研究資料の提案注記の線にも使用 |
| `--color-link-hover` | `--palette-green-950` | `#113a2b` | 同上のリンク、hover |
| `--color-focus` | `--palette-amber-700` | `#78511b` | canvas・subtle・noteに接するfocus輪郭 |
| `--color-border-subtle` | `--palette-neutral-200` | `#ccd3ce` | 表・章・一覧の補助的な区切り。識別をこの線だけへ委ねない |
| `--color-note-surface` | `--palette-amber-50` | `#f5ecdb` | 研究資料の限界・根拠注記の背景。種別は文字でも表示 |
| `--color-note-border` | `--palette-amber-700` | `#78511b` | 同注記の補助線 |

paletteの段階番号は明度・相対輝度の等間隔を表しません。
色対の数値検査と実画面の確認は、知識の正しさの検査とは区別します。
ダークテーマ・半透明・画像背景は実装対象に含めていません。

## 文字の役割と表示条件

日本語と英数字が混在する横組の長文を読むため、以下の8役割を共通CSSで使います。
各 `--type-<役割>-*` は `family`・`size`・`weight`・`tracking`・`line-height` の五つを一組にします。
CSSでは `font` と `letter-spacing` へ割り当てます。これはMimicの閲覧ページの設定であり、DTCG交換形式への準拠や、知識本文で説明する一般的な推奨値を意味しません。

| 役割Tokenの接頭辞 | 書体の参照 | サイズ | 太さ | 字間 | 行高 | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| `--type-body-*` | `--font-family-reading` | `1.0625rem` | `400` | `0` | `1.85` | 本文・通常のリスト・一覧の説明 |
| `--type-page-title-*` | `--font-family-reading` | `2rem` | `600` | `0` | `1.45` | ページのH1 |
| `--type-section-heading-*` | `--font-family-reading` | `1.375rem` | `600` | `0` | `1.55` | H2の章見出し |
| `--type-subheading-*` | `--font-family-reading` | `1.125rem` | `600` | `0` | `1.6` | H3以下の小見出し |
| `--type-catalog-title-*` | `--font-family-reading` | `1.125rem` | `600` | `0` | `1.6` | 一覧の概念名 |
| `--type-supporting-*` | `--font-family-reading` | `.875rem` | `400` | `0` | `1.65` | 版・目次・案内リンク・注記・生成情報・footer |
| `--type-table-*` | `--font-family-reading` | `.9375rem` | `400` | `0` | `1.7` | 表の文字 |
| `--type-code-*` | `ui-monospace, SFMono-Regular, Consolas, monospace` | `.875rem` | `400` | `0` | `1.7` | コードブロック・文中コード |

`--font-family-reading` は `"Gen Interface JP", -apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN", "Yu Gothic", sans-serif` の順です。
ブランド名もこの書体を使います。強調、表見出し、開閉見出しなどは対応する文字役割の太さを600にします。
小見出しと一覧の概念名は現在同じ数値ですが、異なる役割なので独立して管理します。
rootの文字サイズが16 CSS pxの場合、本文は17 CSS px相当です。rootの文字サイズを固定せず、利用者の設定に追従させます。
書体の取得に失敗した場合や対象文字を持たない場合は、後続の書体を使います。そのときの字形や折返しは同一にはなりません。

## 余白の役割と読書幅

本文・一覧・ヘッダー・footerを一列でそろえ、`--layout-reading-width: 42rem` を内容の最大幅にします。
外周の余白を含めたコンテナの幅は、内容幅と左右の `--space-page-inline` の合計です。
画面が狭い場合は画面内に収めます。幅の基準に欧文の文字幅である `ch` を使って日本語の字数を保証しません。

| 役割Token | 通常の値 | 対象 |
| --- | --- | --- |
| `--space-page-inline` | `2rem` | 画面端と内容の間。表示幅42.5rem以下では `1rem` |
| `--space-section-gap` | `2.5rem` | 本文の章間、目次と本文、一覧と題目別案内、footerの前 |
| `--space-heading-content` | `.75rem` | 見出しとその内容の間 |
| `--space-paragraph-gap` | `1.25rem` | 段落後・通常のリスト後・コードブロック前後の組版上の間隔 |
| `--space-list-item` | `.5rem` | 同じリストの項目間、項目内の段落と下位リストの間 |
| `--space-catalog-item` | `1.5rem` | 概念一覧の各項目の上下の内側余白 |
| `--space-catalog-copy` | `.25rem` | 一覧項目内の概念名・説明・版の間 |
| `--space-table-cell-block` | `.75rem` | 表セルの上下。表示幅42.5rem以下では `.625rem` |
| `--space-table-cell-inline` | `.875rem` | 表セルの左右。表示幅42.5rem以下では `.75rem` |
| `--space-surface-inset` | `1rem` | 注記・コードの内側余白、生成情報の左右の内側余白 |

段落間の設定は文章の組版条件として管理し、章や外周の間隔とは用途を分けます。
章の最後にある段落やリストの余分な下marginを除き、章間の距離が重複して増えないようにします。
概念一覧は項目内の概念名・説明・版を近くにまとめ、項目の上下余白と区切りで隣の概念と分けます。
表とコードは狭い画面でその領域を横へ読めるようにし、ページ全体の横幅を押し広げないようにします。

これらの文字と余白の値は、Mimicの対象文章と表示条件に合わせた設定です。数値だけで読みやすさやアクセシビリティを保証しません。
一覧・本文・コード例・出典表について、狭い画面、200%の文字拡大、root文字サイズの変更、代替書体、行高・段落後・字間・単語間の同時変更で、全文と操作が保たれることを実画面で確認します。
