# Mimic閲覧UIのデザインシステム

## 目的と範囲

UIを設計・実装する実務者が、仕事中の疑問から関連知識を見つけ、違い・対象範囲・根拠を読めるようにする。白と黒を基調とし、文章と見出しで長文を読む体験を優先する。この文書はMimicのGitHub Pages閲覧UIに適用する設計と更新の規則である。一般的なデザイン知識の定義や、他の製品への推奨値は定めない。

対象は入口、知識・出典・例を読むページ、関係を調べるページ。正本の知識や関係の意味は変更しない。7つの疑問、その順番、読む理由の短文はこの閲覧UIの編集上の案内であり、正式な概念分類や推奨工程ではない。ユーザーが採用した白黒主体の方向を正式な実装へ適用する。7つの疑問の網羅性、実務者による理解や読みやすさ、実際の読み上げは別途確かめる対象であり、採用だけでは実証済みとしない。

## 判断の原則

- **疑問を入口にする。** 知識の名前を知らなくても、迷っていることから候補の違いを読める。名前が分かる人には24件の一覧も残す。
- **選ぶ理由を見せる。** 知識の名前だけ並べず、それぞれが扱う観点と根拠節を対応させる。短文は本文の代わりにしない。
- **本文を読む時間を守る。** 白地、黒い文字、章の余白、読書幅を基礎にする。カードや状態ラベルを文章全体へ一律に付けない。
- **出典と帰り道を保つ。** 本文・出典・関係を相互にたどり、調べ始めた疑問へ戻れるようにする。画面の違いで用語や動作を変えない。
- **確認の範囲を保つ。** 自動検査、実ブラウザの操作、利用者の理解、読み上げを別の確認として記録する。

背景となる知識は[デザインシステム](../knowledge/design-systems/KNOWLEDGE.md)と[Design Token](../knowledge/design-tokens/KNOWLEDGE.md)、[プロダクト全体のUI設計](../topics/product-ui-design.md)を参照する。これらの本文が、この閲覧UIの具体的な配置や7つの疑問の効果を保証するわけではない。

## Tokenの編集元と変換

`design/tokens.json`を編集元にし、`scripts/design-tokens.ts`で型、参照先、循環、Typographyの五要素を検査してCSS変数へ変換する。独自の小さなToken編集形式であり、DTCG交換形式への適合は主張しない。変換したCSSは`web/reading.css`と結合してPagesのHTMLへ埋め込み、同じToken CSSを`web/tokens.css`としても配信する。共通枠は`scripts/pages-design.ts`、URLの引継ぎと目次は`web/reading.js`、関係探索は`web/graph.js`で管理する。生成物を直接編集しない。

Pagesの色・文字見本は`scripts/design-specimens.ts`で検査済みのTokenから生成する。Markdown本文と生成情報を保持したまま、本文の後に見本を置き、対応する規定と相互に移動できるようにする。

基礎値`base` → 用途`role` → 必要な部品`component`をaliasで結ぶ。例えば`component.question.surfaceOpen → role.color.canvas → base.color.white`。リンク文字は`role.color.link → role.color.text → base.color.ink`で黒に統一する。同じ値でも用途が違うものは別名を保つ。CSSは生成された変数を参照し、具体値の変更は編集元から行う。部品層は疑問の開閉、ナビゲーション、比較候補の3つに限定した。

| 対象 | 共有する判断 |
| --- | --- |
| 色 | 背景・本文・補足・リンク・区切り・focus。lightのみ、全色sRGB・不透明。 |
| 文字 | 本文、見本用の大見出し、ページ題名、章、小見出し、ラベル、補足、コードの8役割。 |
| 間隔 | 要素間・まとまり間・章間・外周と、文章の段落間を別用途として参照する。 |
| レイアウト | ページ76rem、読書40rem、補助列15rem。狭幅では1列に組み替える。 |
| 境界・状態 | 1pxの補助線、3pxのfocus輪郭、4pxの輪郭間隔。開閉は記号と内容の表示で伝える。 |

## 色の役割と組合せ

Pagesの[色見本と組合せ](design-system.html#design-color-specimens)では、Tokenの現在値と背景上の表示を確認できる。見本は`design/tokens.json`から生成し、本文と独立した領域に置く。

リンクの文字は、目次・ナビゲーション・本文・根拠を含め、通常・visited・hover・active・focusの全状態で黒に統一する。操作可能な箇所は下線、太さ、輪郭や配置で識別する。開いている疑問の背景も白にそろえる。青のアクセントはfocus輪郭に残し、文字色や大きな色面には使わない。

| 役割Token | 値 | 組合せ・条件 |
| --- | --- | --- |
| role.color.canvas | #ffffff | 全ページの面。light・不透明。 |
| role.color.text | #171717 | canvasとsubtle上の本文、見出し、黒いナビゲーション。 |
| role.color.muted | #5e5e5e | canvasとsubtle上の補足。 |
| role.color.subtle | #f5f5f5 | コード、表の見出し。開いた疑問の背景には使わない。 |
| role.color.border | #d8d8d8 | 区切りの補助線。境界線だけに意味を委ねない。 |
| role.color.link | #171717 | role.color.textへのalias。全リンクの文字色。canvas・subtle上。 |
| role.color.linkHover | #171717 | role.color.textへのalias。hover/activeでも黒を保ち、下線を太くする。 |
| role.color.focus | #254cbb | canvas・subtleに接する操作輪郭。色だけでなく形を出す。 |

色対の数値は生成後の検査記録へ残す。数値検査は実際の読字やWCAG全体の適合評価ではない。ダークテーマ、透過、写真背景は対象外。

## Typographyと適応

Pagesの[8役割の文字見本](design-system.html#design-type-specimens)では、同じ日本語・英数字の文を各役割の五要素で表示する。書体・文字サイズ・太さ・字間・行高の表示値もTokenから生成する。

各`role.type.*`は書体・文字サイズ・太さ・字間・行高を一組にする。日本語と英数字の横組を対象とし、Gen Interface JP 0.8.0の400・600をPages成果物の同一オリジンに同梱する。`base.family.reading`は`"Gen Interface JP", -apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN", "Yu Gothic", sans-serif`の順。取得できない書体や対象文字を持たない書体は後続へ進む。書体と文字の折返しは環境で変わる。

| 役割 | 文字サイズ | 太さ | 字間 | 行高 |
| --- | --- | --- | --- | --- |
| body 本文 | 1.0625rem | 400 | 0rem | 1.9 |
| display 見本用の大見出し | 2.75rem | 600 | -0.02rem | 1.5 |
| title ページ題名 | 2.25rem | 600 | -0.02rem | 1.5 |
| section 章 | 1.5rem | 600 | -0.02rem | 1.5 |
| subheading 小見出し | 1.25rem | 600 | 0rem | 1.65 |
| label 名称 | 1rem | 600 | 0rem | 1.65 |
| supporting 補足 | 0.875rem | 400 | 0rem | 1.65 |
| code コード | 0.875rem | 400 | 0rem | 1.65 |

codeだけは`ui-monospace, SFMono-Regular, Consolas, monospace`。ほかは`base.family.reading`を共用する。狭幅のdisplayは2.25rem、titleは1.875rem、疑問見出しは1.125remへ切り替える。サイズは`role.responsive.displaySize`・`titleSize`・`questionSize`から基礎値へ参照し、Typographyのほかの四要素は同じ組を保つ。root文字サイズは固定しない。本文の固定高さや行数制限は設けない。表とコードの横スクロールは、その領域内に留める。

## 用語と文体

選び、読む一件の対象は、どの画面でも「知識」と呼ぶ。同じ対象を「概念」「項目」などの別名で呼び分けない。「知識の一覧」「関係を見たい知識」「この知識の関係を見る」を共通の表現にする。

「疑問」は探し始めるきっかけ、「本文」は説明の全体、「出典」は根拠資料、「例」は説明用の作例、「関係」は知識どうしのつながりを表す。これらの役割は統合しない。知識名は正本の題名を使い、「概念モデル」など固有の専門語、本文や引用の「背景」などの見出しも保持する。

見出しだけで対象が分かる場所では、「選択している知識」や「知識」と言い直す補助ラベルを足さない。版、出典、原文などの識別情報は残す。「読む」で本文へ、「関係を見る」で選んだ知識の関係へ進む。要約、閲覧UIの案内文、正本の説明、検証済みの事実を混同しない。原文の否定・条件・対象範囲を短文化で落とさない。

この表現方針は[ui-clarity](https://github.com/9uiLe/ui-clarity)を参照し、Mimicへの適用規則を本書に保持する。Skill本体はRepositoryへ複製せず、利用する環境で管理する。用語をそろえたことだけで、読者の理解が改善したと認定しない。

## 部品とパターン

入口は「疑問から探す」を唯一のH1にし、7つの疑問と同じセクションに置く。独立した紹介用の大見出しは設けず、操作案内は1文に留める。H1は`role.type.section`の組を使い、上余白は`role.space.section`とする。広幅では案内と疑問を左右に並べ、狭幅では案内、疑問の順に1列で表示する。

| 部品・組合せ | 使う場面・状態 | 例外・適用条件 |
| --- | --- | --- |
| 疑問の開閉 | 7つの疑問から候補を比較する。閉時も疑問と内容の手掛かりを表示。開時は候補・読む理由・根拠節を表示。 | 正本本文を隠す部品として一律適用しない。native details/summary、Enter/Spaceで操作する。 |
| 比較する知識 | 名称、扱う観点、疑問とのつながり、根拠節を同じ順序で示す。 | 掲載順を推奨順・必読順とは呼ばない。根拠のない関係や採点を足さない。 |
| 本文の読書 | 章の順序と全文を維持し、目次、出典、Markdown原文を示す。 | 目次と本文の階層を一致させる。短い出典ページには空の目次を作らない。 |
| 関係の探索 | 選んだ知識から、型・向き・statement・scope・evidenceを読む。名前から選び直し、本文と根拠節へ進む。 | 未登録の辺を推測で補わない。未登録と無関係を区別する。URLで選択と元の疑問を保持。 |
| 戻り先 | 共通ナビ、本文・出典・関係の入口へのリンク。 | ブラウザの履歴に依存する「戻る」だけにしない。直接URLでも操作が成立する。 |

疑問の候補は複数を同時に開かず、一つに焦点を置く。本文の目次、関係の根拠、生成情報は個別に開閉できる。目次は初期HTMLでは閉じ、広幅で最初に読み込んだときだけJavaScriptで開く。狭幅では本文開始を押し下げず、利用者の開閉状態はリサイズで変えない。JavaScriptがなくても知識全文と出典は読め、入口の疑問も開閉できる。元の疑問の引継ぎとグラフの選択表示はJavaScriptを使う。

関係を見たい知識の選択にはnative selectを使う。矢印は操作を受け取らないCSS描画とし、枠から`role.space.inline`離す。選択文字には矢印の幅と余白を確保し、キー操作とラベルの関連付けはnativeのまま保つ。forced-colorsでは装飾矢印を外してnativeの表示へ戻す。

## 更新と確認

変更する人は、Token・共通CSS・生成器・ブラウザ処理・この文書の対応を確認する。継続的な保守担当者や独立した承認役は未指定であり、架空の組織や役職を前提にしない。変更理由、影響する用途とページ、例外の条件、実施した確認と未確認事項をPRまたは作業報告へ記載する。READMEを変更履歴にしない。

新しい部品は繰り返す必要が確認できてから追加する。既存部品に合わない場合は、利用者の作業や環境の違いと例外の理由を、この文書の該当箇所へ反映する。値が同じという理由だけで用途を統合しない。Token変更時は参照する部品とページを追い、用途や五要素の説明も更新する。

入口の疑問・候補・読む理由と根拠節は`design/reading-paths.json`を編集する。知識のIDと節への参照を保ち、案内の編集を知識本文や関係型の変更として扱わない。本文は`knowledge/`、意味付き関係は`relations/`の正本から生成する。配信対象は公開一覧に明示し、新しい外部依存や公開ファイルを暗黙に増やさない。

生成と検査は[開発・公開ガイド](https://github.com/9uiLe/mimic/blob/main/guideline/development.md)と[品質検査](https://github.com/9uiLe/mimic/blob/main/guideline/quality-checks.md)に従う。Tokenだけの変更でも、使う部品と代表的な読書・比較・関係探索を確認する。確認する一巡は「疑問→候補の比較→本文→出典→入口」と「本文→選んだ知識の関係→対象本文または根拠節→元の疑問」。狭幅、キーボード、200%の文字拡大、root文字サイズ、代替書体、文字間隔等の変更を対象環境で確かめ、対象と観測結果を記す。

自動検査、実ブラウザでの操作、人による理解、実際の読み上げは区別して報告する。検査の成功から使いやすさ、知識の正しさ、アクセシビリティ全体の適合を推測しない。未実施の確認は成功として記録しない。公開・`main`へのpushは[利用ガイド](README.md#実行前に確認する操作)の許可対象であり、ローカル生成や方向の採用から公開許可を推測しない。
