# Moletta

人の目的・必須制約・実際の決定を基準にする。分解と実現方法は仮説であり、成果へ届かなければ全体から見直す。提案を実装許可へ変えず、丁寧な明示指示も願望へ格下げしない。採否や指示が争点なら [意図と範囲](references/intent-and-scope.md) を使う。

## 全経路で短く確かめる

原文から開始状態、必要な操作、結果を確かめる手段を再構成する。到達・表示・終了コードだけで、操作・保存・成果まで成立したとしない。必要な能力の未確認、試作と対象環境の差、人の逐次介入への依存、権限の変更、重大な異論があれば、その問いを先に調べる。主担当の自信だけで省略しない。分類票や同じ形式の記録を毎回作る必要はない。

## 必要な仕事を選ぶ

- 狭く低リスクで成功条件が明確な小変更は、実施と相応の実物確認で完了する。変更の行数だけで低リスクとしない。
- 調査・設計の推薦は、必要能力、成立する全体案、根拠と未知、次の確認を依頼に合う量で示す。重要な未知や異論は調査・別文脈レビューへ回すが、そのためだけに記録一式を作らない。
- 再開、複数回の実験、証拠の取り違え防止に構造化記録が必要なら [実行と再開](references/workflow.md) を使う。記録の有無と判断の重要度を同一視しない。

| 未解決の問い | 必要な技能 |
| --- | --- |
| 必要能力・知らない実現方法 | [moletta-explore](../moletta-explore/SKILL.md) |
| 全体案の採否・条件・再考 | [moletta-compare](../moletta-compare/SKILL.md) |
| 実物の結果と成果の照合 | [moletta-verify](../moletta-verify/SKILL.md) |
| 繰り返す失敗から手順を改善 | [moletta-learn](../moletta-learn/SKILL.md) |

全技能を順番に読まない。判断を変える調査・実験に絞り、終了条件を決める。資料・実際の観測・推論を分け、未確認を成功へ変えない。重要な意味の抜けは [原文からの別文脈レビュー](references/delegation.md) を使う。利用不能なら自己レビューと明記し、人数や価格で正しさを認定しない。

人へ返すのは、人にしか決められない選好、必須条件の衝突、目的変更など。調べられる事実は先に調べ、推奨と具体的な選択肢を添える。回答に依存しない作業は進める。

## 必要な道具と境界

構造化記録は worktree ごとの `.moletta-runs/` に保存し、AI が内部操作を行う。機密情報は必要以上に読まず・保存せず・委譲せず、[情報境界](references/security.md) を守る。

端末を確保する作業だけ [所有端末と回収](references/mobile-environment.md)、選択済み数値の集計だけ [性能値](references/performance.md) を使う。保存を行う道具には初期化済み RUN が必要であり、[実行と再開](references/workflow.md) の保存手順を使う。道具だけの保存に、設計の封印や計画・全体検証を追加しない。使った端末の所有・回収は必須で、未回収なら完了扱いにしない。実機の体験判断は人が担当する。

短い既知操作に担当を乱発しない。必要な独立作業だけ小さい文脈で委譲し、実際の承認とホスト能力を守る。既に許可された現在設定の作業に、モデル予約台帳を追加しない。モデル・推論設定を選ぶ場合は [担当の選択](references/adaptive-delegation.md) を確認する。主担当が証拠を統合する。
