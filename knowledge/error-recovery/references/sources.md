# エラーからの回復の出典

| 出典 | 確認箇所と本文で使う範囲 |
| --- | --- |
| [Tim Neusesser・Evan Sunwall — Error-Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/) | Visibility Guidelines、Communication Guidelines、Efficiency Guidelines。エラーの発見、平易で具体的な説明と回復の支援、利用者の作業を保つことを扱う実務記事。 |
| [W3C — WCAG 2.2](https://www.w3.org/TR/WCAG22/) | [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) と [3.3.3 Error Suggestion](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html)。自動検出した入力エラーと、修正案が既知でセキュリティや内容の目的を損なわない場合のWeb要件。 |
| [GOV.UK Design System — Error summary](https://design-system.service.gov.uk/components/error-summary/) | When to use this component、How it works。要約と個々の入力エラーを提示し、該当箇所へ案内する実装例。 |
| [Seckler et al. — Designing Usable Web Forms（CHI 2014）](https://doi.org/10.1145/2556288.2557265) | [バーゼル大学配布PDF](https://edoc.unibas.ch/server/api/core/bitstreams/a4d3ea7f-518a-4ca4-b13a-f799f6781740/content) の Method、Results / Successful form submissions（Table 3）、Conclusion。指針を組み合わせた三つのフォームの統制比較。差をエラー表示単独の効果や、他のUIの達成率へ転用しない。 |

失敗と結果不明を区別する例や、二重処理が起きる場合の調べ方は、保存などの操作に回復の考え方を適用したMimicの例です。
