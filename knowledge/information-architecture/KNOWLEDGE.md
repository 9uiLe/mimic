# 情報アーキテクチャ

## 概念

情報アーキテクチャ（Information Architecture、IA）は、情報や機能を何として定義し、どのように組織し、関係付け、名付けるかを扱います。
NN/gのJen Cardelloは、WebサイトのIAを、内容・機能の特定と定義、およびそれらの関係を定める構造・組織・命名から説明しています。
この本文は、その区別を中心に、デジタル製品の全体構成を読むための説明を加えます。

たとえば「記録」と呼ぶ情報が、保存した一件を指すのか、記録する行為を指すのかで、分類や名称の意味が変わります。
これはMimicの説明用の例です。画面に置く言葉を決める前にも、扱う対象が何かを明らかにする問題があります。

## 背景と立場

Cardelloの説明は、Webサイトとイントラネットを対象に、IAと画面に見えるナビゲーションを区別するものです。
内容の量や複雑さを把握せずに見た目からナビゲーションを選ぶと、情報の構造を部品の都合へ押し込めることになります。
同記事は、試作前にIAを完全確定することまでは求めず、まず構造の検討を行う必要を述べています。

GOV.UKのコンテンツ指針は、似た内容をまとめ、利用者がトピックや作業を調べられるようにしています。
その階層的なトピック分類は、GOV.UKという大きな情報群を運営する具体例です。
すべての製品が同じ階層数や分類語を採用するという意味ではありません。

## IAとナビゲーションの違い

IAは情報・機能の構造を扱い、ナビゲーションはその構造の中で内容へ到達するためのUIを扱います。
同じ内容を、一覧からたどる場合と、検索や関連項目から開く場合では、見える経路が異なります。
経路が複数あることと、到達する情報そのものが別であることは区別できます。

| 考える対象 | 説明すること |
| --- | --- |
| 情報・機能の定義 | 何を扱い、それが何を意味するか |
| 分類と関係 | どのまとまりに属し、他の対象とどう結び付くか |
| 命名 | 分類や対象を、どの言葉で識別するか |
| ナビゲーション | どの入口や経路から対象へ到達できるか |

この表は原典の定義を読み分けるための整理であり、四段階の設計手順ではありません。
画面一覧は表示する場所を示せますが、それだけでは、各画面が扱う情報の意味や関係まで説明できません。

## 分類、表示上のまとまり、理解の枠組み

情報を同じ分類に含めることと、画面上で隣に置くことは異なります。
[グルーピング](../grouping/KNOWLEDGE.md)は、意味に沿った分類と、近接で感じ取るまとまり、名称を区別します。
分類が曖昧なまま余白だけを整えても、何を同じものとして扱うかは決まりません。

[概念モデル](../conceptual-models/KNOWLEDGE.md)は、利用者が構成要素や動作を理解する枠組みを扱います。
IAで定めた構造を、利用者がそのまま理解するとは限りません。
名称や経路を含め、製品がどのような関係を伝えているかを考える必要があります。

## 製品全体で考えること

一つの画面だけを見ると、そこで必要な項目を置くことに関心が向きます。
IAでは、その項目が他の場所でも同じ意味を持つか、どこから探す対象か、関連する情報へどうつながるかも扱います。
利用者の目的を理解する[人間中心設計](../human-centered-design/KNOWLEDGE.md)と結び付けることで、実装上の区分だけで分類を決めることを避けられます。

GOV.UKでは、一組の資料を同じ場所で見る必要と、順に作業を進める必要を区別しています。
前者に使う文書コレクションを、作業の案内に転用しないという同組織の指針です。
この例は、関連情報の集合と、行為を進める順序が別の問題であることを説明します。
行為とシステムの応答は[インタラクションデザイン](../interaction-design/KNOWLEDGE.md)で扱います。

## ネイティブアプリへの射程と限界

WebのIAとナビゲーションの区別は、アプリの構造を説明する際にも役立つ整理として使えます。
この応用は、Web向け記事がネイティブアプリの設計を直接規定するという主張ではありません。
AppleのiOS向け解説も、タブが既に明確な情報のまとまりを表し、階層を反映することを説明しています。
ただし、Appleの具体的なナビゲーション指針は、プラットフォームと発表時点を持つ資料として読みます。

IAは、すべての情報を一つの木構造へ押し込めることや、画面数を減らすことを目的とする語ではありません。
構造の説明だけで、その名称が利用者に理解されるか、目的の情報が見つかるかは確かめられません。
個別製品への適用では、利用者、内容、利用環境を踏まえた確認が別に必要です。
