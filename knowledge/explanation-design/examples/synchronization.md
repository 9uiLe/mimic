# 同期システムで「保存」と「同期」を説明する

この例はMimicが作成した架空の説明例です。特定製品の仕様、利用者実験の結果、万能な情報選定手順ではありません。
[説明の選択と忠実さ](../KNOWLEDGE.md)の区別を、情報の選択に当てはめて読むために使います。

## 仮定した仕組みと利用者の問い

ノートは端末内へ保存してから、通信可能なときにサーバーへ送信されます。
サーバーが保存を受理した確認を受けた後に「同期済み」となり、別端末が取得して初めてそちらに現れます。
同時編集には競合が起こり得るとします。再試行間隔や競合の解決方式はこの例では未定義です。
利用者の問いは「保存したのに、なぜ別の端末に見えないのか」です。

この問いでは、期待した「保存すれば別端末にも現れる」と、実際の「端末内に保存した」を対比します。
保存、送信、別端末の取得という関係を省いて「保存済みだから大丈夫」とだけ伝えると、仮定した仕様に忠実ではありません。
問いの対比と説明範囲の区別は[本文](../KNOWLEDGE.md)のE1・E2に対応します。

## 情報の扱いを区別する

以下はこの仮定での作例です。「今は見せない」は、情報が存在しないという意味ではありません。

| 情報 | 作例での扱い | 理由・条件 |
| --- | --- | --- |
| 端末内への保存と同期は別であること | 今見せる | 期待との食い違いを説明する中心的な関係。 |
| 現在の保存状態、通信状態、最後に確認できた同期時刻 | 取得できた範囲を今見せる | 一般的な仕組みと、この端末の観測事実を区別する。取得できなければ不明と示す。 |
| 次に試せる操作と、その操作が何を変えるか | 今見せる | 説明を使って状態を確認できるようにする。 |
| 保存→送信→受領確認と、別端末の取得の関係 | 短い文章と段階ごとの表で見せる | 単なる部品一覧より、この問いに必要な状態の違いを表せるという作例上の判断。 |
| 接続ログ、再試行の詳細、プロトコル | 内容の分かる詳細への入口を置く | 通常の説明と切り分け、原因調査の際には読めるようにする。 |
| 編集を破棄する競合解消操作を提示する場合、その操作で失われる編集 | その操作の前に見せる | この場面で操作結果を変える条件を、装飾的な詳細と同じ扱いで省かない。 |
| 製品の開発史や問いに無関係なアニメーション | この説明から省く | 保存と同期の区別を説明する役割が、この作例ではない。 |
| 未確認の障害原因や完了までの秒数 | 事実として提示しない | 説明の短縮とは別に、根拠が不足している。 |

詳細を後に回すことと、重要な条件を隠すことの区別は[判断材料の選定](../../../topics/decision-material-selection.md#情報を示す時点と部品の違い)も参照します。

## 形式を変えるときに保つ関係

| 状態 | この仮定で言えること | まだ保証しないこと |
| --- | --- | --- |
| 端末内に保存 | この端末に変更が記録された | サーバーへの到達、別端末への反映 |
| 同期済み | サーバーの受領を確認した | 別端末が最新の内容を取得したこと |
| 別端末に反映 | その端末が変更を取得した | 以後のすべての編集が競合しないこと |

状態を同時に比較したいなら上の表、送信や取得の順を追いたいなら段階図・シーケンス図が候補になります。
動き自体を読む必要がなければ、自動再生だけに情報を載せる必然性はありません。
これは[マルチメディア学習](../../multimedia-learning/KNOWLEDGE.md)を参照して作った表現の比較で、表の優位を実証したものではありません。
図だけにせず、同じ関係を文章でも読めるようにします。

## 理解を確かめる問いの例

「分かりましたか」だけでなく、「通信が切れている間に編集すると、別端末には何が見えそうか」を聞くと、保存と同期を区別しているかを調べられます。
答えが違う場合は、用語、状態の区別、前提の誤りなど、どこに食い違いがあるかを調べます。
一つの正答だけから、以後の操作や未知の障害への対応がすべてできるとは判断しません。
[メンタルモデル](../../mental-models/KNOWLEDGE.md)の理解と自己評価の区別、[本文](../KNOWLEDGE.md)のE5に対応する作例です。

## AIが判断理由を残す説明例

AIがこの例を適用するなら、目的、確認済みの仕様、仮定している既有知識、今見せる情報、後に回す情報と入口、形式を選んだ理由を分けて説明できます。
「保存と同期が同じだと思っている」は仮説であり、利用者の確定した属性ではありません。
採用する判断とその確認は[設計判断台帳](https://github.com/9uiLe/mimic/blob/main/contracts/product-design.md)で扱います。
ここに挙げた記録項目は作例を読み解くためのもので、新しい必須スキーマや自動判定規則ではありません。
