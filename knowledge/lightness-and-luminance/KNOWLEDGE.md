# 明度と相対輝度

## 概念

UIで「明るくする」と言うとき、人が感じる見え方、色空間の座標、計算に用いる量が混ざることがあります。
明度と相対輝度を区別すると、何を変え、何を確認する話なのかが明確になります。
ここでは次の区別で説明します。この章立てはMimicの整理です。

| 対象 | 何を扱うか | 同一視しないもの |
| --- | --- | --- |
| 知覚的な明度 | 人の見え方に対応させて表す明暗 | RGB成分の単純平均 |
| HSLのL | HSLという色表現のlightness成分 | 知覚的に均等な明度の尺度 |
| WCAGの相対輝度 | 色空間中の明るさを正規化した計算量 | HSLやOklabのLそのもの |

同じ「L」という文字でも、色空間や規格が違えば意味と尺度が異なります。
色の座標を示すときは、どの色空間の成分かを添えます。

## 背景：操作のしやすさと見え方の記述

CSS Color 4 §7は、RGBから色を直感的に調整しにくいことを背景に、HSLを説明しています。
HSLは色相H・彩度S・明度LでsRGBの色を表す方法です。
HSLで同じLを指定しても、異なる色相の色が同じ明るさに見えることまでは意味しません。

一方、同仕様§9.1は、Labを知覚上の間隔に対応させることを目指した色空間として説明しています。
LabのLと相対輝度の等間隔は、見え方における等間隔という点で異なります。
OklabとOkLChにも明度Lがあり、§9.4でその表現を定めています。
HSLのL・LabのL・OklabのLは、名前が似ていても値をそのまま交換できません。

これは、機械で扱いやすい表現と、知覚に対応する表現の目的の違いです。
知覚に対応する尺度を使ったことだけで、すべての利用者の見え方が同じになるわけではありません。
参照したCSS Color 4は2026年10月20日のCandidate Recommendation Draftです。
確定済みのW3C Recommendationとしては扱いません。

## 色相・彩度・クロマとの違い

色相は色の系統を表す成分です。明暗だけを表すものではありません。
HSLのSはその色空間における彩度、OkLChのCはクロマを表します。
どちらも色みの強さに関わりますが、別の定義・尺度です。
HSLのSとOkLChのCを同じ数値にすれば同じ色みになる、とは解釈しません。
同様に、色相を変えただけで文字のコントラスト条件を満たせるとは限りません。

## WCAGの相対輝度

WCAGの相対輝度は、最も暗い黒を0、最も明るい白を1として正規化します。
sRGBの8bit各成分を255で割った値をcとし、各成分を次のように変換します。

```text
c_linear = c / 12.92                     （c ≤ 0.04045）
c_linear = ((c + 0.055) / 1.055) ^ 2.4  （それ以外）
L = 0.2126 R_linear + 0.7152 G_linear + 0.0722 B_linear
```

これは[W3Cの公式解説の定義](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#dfn-relative-luminance)に基づきます。
エンコードされたRGB値を、そのまま係数付きで足す式ではありません。
また、このLはディスプレイの実測輝度を表すcd/m²の値ではありません。
本記事の式はsRGBを対象とし、別の色空間の成分へ無条件に適用しません。

二つの色の相対輝度を組み合わせると、[色コントラスト](../color-contrast/KNOWLEDGE.md)の比を求められます。
色単体の明度や相対輝度と、背景とのコントラスト比は別の量です。

## UIへの適用と関連する概念

明度を調整することと、背景とのコントラストを確認することは別の判断です。
「補助文を少し薄くする」という表現だけでは、変える色の数値や、組み合わせる背景が定まりません。
色空間と値を特定し、前景と背景の関係を[色コントラスト](../color-contrast/KNOWLEDGE.md)で確認します。

[Design Token](../design-tokens/KNOWLEDGE.md)は、こうした判断を名前と値で共有・管理する段階で関係します。
明度や相対輝度を理解するための前提ではありません。
Mimicで具体的なUI色を示すときは、[色提示方針](https://github.com/9uiLe/mimic/blob/main/guideline/README.md#uiの色を具体的に示すとき)に従い、用途・値・背景と条件を示します。

[色への適用例](../design-tokens/examples/color-presentation.md)では、主要本文と補助文を同じ背景と組み合わせています。
paletteの段階番号は作例の名前であり、知覚明度や相対輝度の等間隔を表しません。
Token名にprimaryやsecondaryがあることも、測定結果の代わりにはなりません。

## 対象範囲と出典

本記事は、UIの色を説明する際に、用語・数値・確認対象を混同しないための基礎を扱います。
周囲の色による知覚の変化、色彩教育の歴史、文化に共通する色の心理的意味は扱いません。
CIE原典に基づく厳密な用語体系の解説も、本記事の範囲外です。

[出典と説明の範囲](references/sources.md)に、CSSの色表現とWCAGの計算量の対応を記載します。
色の記述仕様を、普遍的な配色の正解や実画面の読みやすさの保証へ広げません。
