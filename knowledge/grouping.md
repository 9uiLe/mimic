# グルーピング

## 目的と適用条件

利用者の目的・作業・情報の意味に沿って、何をひとまとまりとして扱うかを決めます。関連する情報を探したり、比較したりするときの手掛かりを作るために使います。

情報の分類を決めることと、余白や囲みで見た目のまとまりを伝えることは分けて考えます。作り手のデータ構造や、近くに置けるという理由だけで分類を決めません。少数の情報なら、グループを増やさず一つの一覧で足りる場合もあります。

以下の手順と例は **Mimic の提案**です。ブランディングと個人の好みは判断軸に含めません。

## AI が確認する入力

- 利用者が何を探す・比較する・把握するのか。
- 情報の意味・関係と、利用者に分かる分類名。
- 一つのまとまりの中だけで判断できるか、まとまりをまたぐ比較が必要か。
- 複数の分類へ属する項目や、分類しにくい例外。
- 分類・絞り込みによって伝わる文脈と、見えなくなる情報。

## 判断手順

1. **目的に対応する分類軸を候補にする。** 時間、作業、対象など、何を一緒に見たいかから考える。どの軸も常に正しいとは扱わない。
2. **同じ情報を異なる軸で並べて比較する。** 目的の情報を見つけられるか、比較のために行き来が増えないかを確かめる。一つの一覧の案も残す。
3. **境界と名称を確かめる。** 利用者の言葉で内容を予測できる名称にする。複数所属や例外を無理に一つへ押し込めない。
4. **分類で失われる手掛かりを確認する。** 別グループの緊急事項や、横断して比較すべき情報が見えなくならないか調べる。必要な情報を隠す理由にしない。
5. **表示と選定へつなぐ。** グループ名・対象範囲が伝える文脈を記録し、各行で繰り返す項目が必要か見直す。見出しや余白で境界を伝え、利用者が目的を達成できるか確かめる。

## AI が返す内容

| 内容 | 残すこと |
| --- | --- |
| 分類案 | 分類軸、グループ名、含まれる情報、例外・複数所属 |
| 採用理由 | 支える利用目的と、別の分類軸や一つの一覧を採用しない理由 |
| 表示への影響 | 一覧の範囲、残す項目、横断比較や緊急事項への到達方法 |
| 適用の限界 | 仮定、分類で探しにくくなる情報、未確認事項と検証方法 |

## 説明用の例

### 共通データと仮定

次の4件は、[視覚的な優先順位の例](visual-hierarchy.md)でも使う架空の予定です。現在は当日の9:00、すべて未完了とします。

| 所属 | 日時 | 内容 |
| --- | --- | --- |
| 仕事 | 今日 10:00 | 会議 |
| 仕事 | 今日 17:00 | 資料の提出期限 |
| 私用 | 明日 14:00 | 歯科の予約 |
| 私用 | 週末・時刻未定 | 旅行の準備 |

### 条件 A：次の時刻付き予定を知りたい

「今日」「明日以降」に分け、それぞれの中で時刻順に並べる案を考えます。現在9:00なら、次の時刻付き予定は10:00の会議です。17:00の提出期限も、時刻付きの項目として残します。

この目的では、仕事と私用を最初に分けると、次の予定を探すために両方を見る必要が生じます。一方、4件だけなら一つの時系列一覧で十分かもしれず、日付グループを作る効果は未検証です。時刻未定の旅行準備は、その状態が分かるように扱います。

時刻順は、業務の重要度順や、今から取り組むべき順ではありません。提出準備にかかる時間などが不明なので、この例から仕事の着手順は決められません。

### 条件 B：仕事と私用を分けて全体を把握したい

「仕事」「私用」に分け、両方を同じ階層で見渡す案を考えます。日時は各項目に残します。日付だけで分類すると、仕事の予定全体を探すために複数の日付を見る必要があります。

ここで両グループを同程度に見つけやすくするのは、**両方へ同程度にアクセスする必要があるという追加の仮定**です。4件のデータだけから導いた結論ではありません。また、件数では所要時間や負担は分かりません。

同じ4件でも、目的によりまとまりを変えます。分類しただけで情報数が減ったり、優先度が決まったりするわけではありません。

## 未検証事項

- 4件では、日付のグループを作る案が一つの一覧より探しやすいか。実際の課題で発見の正確さと時間を比較する必要がある。
- 分類名を利用者が予測どおりに理解できるか。例外や複数所属でも迷わないか。
- 件数が多い場合、グループをまたぐ比較や、別グループの緊急事項に気づけるか。
- グループの文脈によって行の項目を省く場合、その文脈が利用者に伝わるか。
- 出典の現行内容・リンク到達性。適用時の原文再照合は未実施。
