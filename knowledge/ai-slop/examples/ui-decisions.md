# 説明・囲み・番号を選ぶ例

[AI Slopの本文](../KNOWLEDGE.md)を踏まえ、使用を控える条件と必要な反例を示します。
すべてMimicが作成した説明用の例です。原典の実験結果や、生成品質を実証した指示集ではありません。
情報の必要性は[Aesthetic and Minimalist Design](../../aesthetic-and-minimalist-design/KNOWLEDGE.md)、
まとまりと強調は[グルーピング](../../grouping/KNOWLEDGE.md)・[視覚的な優先順位](../../visual-hierarchy/KNOWLEDGE.md)を参照します。

## 例1：同じ意味の説明を重ねない

利用者が行うことや判断することに役立たない説明を、見出しの下へ自動で追加しない。
NN/Gは、不要な情報が必要な情報の可視性を下げる一方、必要要素の不足も問題だと説明する。（[Aesthetic and Minimalist Designの出典](../../aesthetic-and-minimalist-design/references/sources.md)）

**省く条件**：見出し・操作名・配置ですでに伝わり、補足を消しても目的・対象・制約が失われない。
**残す条件**：入力形式、情報の用途、操作の影響など、利用者が推測できない情報を伝える。
GOV.UKのhintは多くの利用者に必要な補助情報を短文で扱う。入力ラベルは必要とする。（[GOV.UKとWCAGの出典](../../aesthetic-and-minimalist-design/references/sources.md)）

説明用の作例。利用者の目的を「自分の通知設定を変更する」と仮定する。

```text
変更前候補                 変更案
通知設定                   通知設定
通知設定を管理できます     [メール通知：オン]
[メール通知：オン]
```

「通知設定を管理できます」はこの仮定では新しい判断材料を加えないため、省く候補になる。
反対に「契約に関する重要なお知らせは、オフでも送信します」は設定範囲の制約なので残す。
セカンダリという視覚上の扱いだけで、情報の要否を決めない。

**AI向け指示案**：補足文ごとに、見出しや操作名にない判断材料を挙げる。
新しい情報を加えない文は省く候補とする。対象・単位・制約・入力ラベルは別に確認する。
この指示案はMimicの編集仮説であり、生成品質の向上を確認した手法ではない。

## 例2：カードの境界に、まとまりとしての理由を持たせる

Fluent 2は、近接や間隔で関係を表し、線などを使わずに内容を分節できると説明する。（[Fluentの出典](../references/sources.md)）
これは余白がどんな意味でも伝えるという主張ではない。分類の意味には名称が必要な場合がある。

**省く条件**：同じ対象に属する属性を一つずつ囲んでも、独立した対象・操作・領域を示さない。
**残す条件**：異なる内容を各対象の単位でまとめ、個別の詳細へ導くなど境界に役割がある。
NN/Gはカードを関連情報の概念単位として説明し、異種の内容を扱う用途を挙げる。（[カードの出典](../references/sources.md)）

説明用の作例。請求書1件の確認を仮定する。角括弧は囲みの有無を説明する記号である。

```text
変更前候補                         変更案
[請求番号 INV-042] [支払期限 10/31]  請求書 INV-042
[請求額 12,000円]                   支払期限 10/31  請求額 12,000円
```

別の請求書まで一つにまとめる案ではない。各属性を個別に囲む必要があるかを検討する例である。
関連しないレポートや案件をそれぞれまとめるカードは、この例だけでは省く根拠にならない。

**AI向け指示案**：囲みを加える前に、境界が表す対象と、その内外の意味の違いを書く。
違いがなければ、近接・余白・見出しで表せるか検討する。カードを一律に禁止しない。
この指示案はMimicの編集仮説である。

## 例3：番号で表す順序があるか確かめる

Anthropicの公開指針は、構造要素に情報を持たせ、段階的な手順や時系列など
実際に順序のある内容に番号を使うよう述べる。（[Anthropicの指針](../references/sources.md)） これは同社のデザイン指針である。

**省く条件**：並列の機能やカテゴリに、手順や時系列を表さない番号を装飾として付けている。
**残す条件**：申請の手順、履歴の時系列など、順番が内容の理解や行動に関わる。
番号が手順・順位・参照IDのどれを表すかも区別する。識別に使う番号まで自動で削らない。

説明用の作例。利用者はどちらの機能から使ってもよく、手順ではないと仮定する。

```text
変更前候補                       変更案
01 カレンダー                    カレンダー
02 メモ                          メモ
```

「1. 入力 → 2. 確認 → 3. 完了」という申請の進行なら、順序に意味があるため残す。
**AI向け指示案**：番号を加える前に、順番を入れ替えると意味が変わるか確認する。
番号が識別や参照のために必要かも確認し、伝える情報がなければ省く。この指示案も編集仮説である。

## 「レイアウトに説明させる」の範囲

関係や強調を配置で伝えることと、必要な名称・文脈・操作説明をなくすことは別である。
Webでは、見た目が伝える情報・構造・関係をプログラムで解釈可能にするか、テキストで提供する。（[WCAGの出典](../../aesthetic-and-minimalist-design/references/sources.md)）
入力にはラベルまたは説明が必要であり、見出しとラベルは主題・目的を説明する。（[WCAGの出典](../../aesthetic-and-minimalist-design/references/sources.md)）
既存の見出しを入力ラベルとして兼用できる場合もあるが、意味と関連付けを保つ。（[GOV.UKとWCAGの出典](../../aesthetic-and-minimalist-design/references/sources.md)）
