# データフロー図（DFD）

## 概念と背景

データフロー図（Data Flow Diagram、DFD）は、情報がどこから入り、どの処理を経て、どこへ保存・送信されるかを表す図です。
構造化分析・設計の系譜にあり、データの移動と変換を中心にシステムを説明します。
処理の順序や条件分岐を中心にする制御フロー図とは、矢印が表すものを区別します。

| 要素 | 表すもの | 説明用の名前 |
| --- | --- | --- |
| 外部実体 | 対象範囲の外で情報を渡す・受け取る人やシステム | 購入者、決済サービス |
| プロセス | 情報を扱い、変換する処理 | 注文を受け付ける |
| データストア | 後で使う情報の保存先 | 注文記録 |
| データフロー | 要素間を移動する情報と方向 | 注文内容、決済結果 |

Yourdon系とGane–Sarson系などで形が異なります。図の冒頭に採用した記法と凡例を示し、異なる意味の記号を混ぜません。

## 使い所

| 調べたいこと | 図に含める範囲 |
| --- | --- |
| 外部とのデータ交換 | 対象を一つの処理として示すコンテキスト図 |
| データの生成・変換・保存 | 主要処理とストアに分けた詳細図 |
| 実装への対応 | 実際のソフトウェア・ファイル等を示す物理的なDFD |
| セキュリティ上の入口や境界 | データフローに信頼境界と対象資産の説明を加えた図 |

論理的なDFDでは業務上必要な情報の移動、物理的なDFDでは実装を説明します。
抽象度と対象範囲を題名に書き、詳細を増やすときは別の図へ分解します。
「コンテキスト」「レベル1」などの呼び方だけに頼らず、何を一つの処理としたかを明示します。

## 作り方のポイント

処理は動詞句、ストアと流れる情報は名詞句で記します。「送信」だけでなく「注文内容」のように、何が移動するかを書きます。
入力と出力を区別し、保存先に到達する処理も示します。外部実体とストアを直結すると、情報を受け付ける処理が省かれてしまいます。
詳細図に分ける場合は、上位図の入力・出力がどこへ対応するかを追える名称にします。

OWASPの脅威モデリングでは、信頼の前提が変わる場所を信頼境界として加えます。
これはデータ移動の説明にセキュリティの観点を加えた使い方です。サーバーやネットワークの境界と常に一致するわけではありません。
同じ管理範囲に見える要素でも、権限や入力への信頼が違う場合は、その条件を図と文章で説明します。
境界を描いたこと自体は、認証・認可・暗号化の実装や安全性の確認を意味しません。

## 他の図との違い

[ER図](../entity-relationship-diagrams/KNOWLEDGE.md)がデータの種類と関連を表すのに対し、DFDはデータの移動と処理を表します。
DFDの一本の線から、呼び出し順序、同期・非同期、トランザクション境界、所要時間は読み取れません。
順序や分岐は[UMLのシーケンス図・アクティビティ図](../uml/KNOWLEDGE.md)で補います。
この使い分けは、各図の対象の違いを説明するための整理です。
