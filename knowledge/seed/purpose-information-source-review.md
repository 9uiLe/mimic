# Purpose and information hierarchy source review

Reviewed 2026-10-09. Public first-party pages and their indicated actual
screens were checked in the user's Mac Chrome. The observations below do not
establish effectiveness in Mimic. No third-party screenshot, asset, or long
passage is copied into the repository.

| Case                        | Author / source                                                                                                                                            | Observed on source                                                                                                                                                                                                                           | Mimic transfer hypothesis and limit                                                                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Proposal comparison         | SmartHR Design System, [common table](https://smarthr.design/products/design-patterns/smarthr-table/)                                                      | Guidance for identifying/comparing fields, status and row actions; the overview table screen was visually inspected.                                                                                                                         | Show only differentiating proposal attributes plus status and action; first check that an omitted field cannot change a decision.                                               |
| Object context              | 朴木優斗 / teamLab, [object-oriented UI Speaker Deck](https://speakerdeck.com/teamlab/object-oriented-ui-design)                                           | The 65-slide deck transcript and selected slide images were checked in the 9UI-179 review; slide 48 was visually inspected. The bookshelf example moves from collection to selected book and contextual actions.                             | For persistent design proposals, distinguish collection facts from object details. Do not assume an object collection helps a short procedure or copy the bookshelf.            |
| Bounded detail              | GOV.UK Design System team, [Details](https://design-system.service.gov.uk/components/details/)                                                             | The live example was visually inspected collapsed and expanded. Its guidance says use for one optional section and not for information the majority needs. It also notes that some users mistake the disclosure for navigation.              | Place supplementary explanation behind an explicit, descriptive trigger; avoid hiding a decision-critical caveat. A discoverability test is needed.                             |
| Multi-session task progress | GOV.UK Design System team, [Complete multiple tasks](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)                               | The illustrated live task list was visually inspected: grouped tasks with completed/incomplete labels and links. Guidance limits the pattern to long transactions over multiple sessions and advises simplifying tasks before adding a list. | Group Run or design workflow stages only where the person needs to resume and understand an actionable state. Do not convert every internal step into user-visible work.        |
| Nested run state            | Amarilis Dias / GitHub, [Improving navigation for GitHub Actions](https://github.blog/news-insights/product-news/improving-navigation-for-github-actions/) | 2022 first-party article and Run jobs screenshot visually inspected (see `product-ui-source-review.md` after 9UI-179 integration).                                                                                                           | Show parent/child state with a route into diagnostic detail only if the current Run has nested or parallel work. The article does not prove current GitHub UI or Mimic results. |

Mimic's own [README](../../README.md), [design-space contract](../../docs/specifications/design-space-exploration.md), and [local monitor guide](../../docs/development/workspace-monitor.md) were read to distinguish the intended Design Package outcome and human decision from the monitor's diagnostic role. Those repository files are product-scope evidence, not empirical user research. The target Problem Profile and UI Contract may narrow or change the hierarchy. All external source links were public; no login, paywall bypass, or new permission was needed.
