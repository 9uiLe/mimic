# 同期状態を説明できることと、名称を知っていること

メンタルモデルについての区別を説明するために作成した架空例です。
特定製品の仕様、利用者の実測結果、採用すべきUIではありません。

## 仮定する仕組み

ある文書アプリは編集を端末に保存し、接続があるときにサーバーへ送ります。
この例の「端末に保存済み」は端末内の保存完了、「同期済み」はサーバーが保存を受理した状態を表します。
競合解決などの詳細は例の対象外です。実際の製品にこの状態定義をそのまま当てはめることはできません。

| 観察できたこと | 読み取れる範囲 |
| --- | --- |
| 「同期済み」という表示名を答えた | 名称を再生できた |
| 接続が切れたまま編集すると、端末には残るが別端末にはまだ届かないと説明した | この条件で端末保存とサーバー保存を区別できた |
| 初めて示された別端末の事例で、同期前の内容は見えないと予測した | その新規事例で関係を利用できた |
| 「よく分かった」と答えた | 本人が理解できたと感じている |

四つの観察は同じ意味ではありません。自信が高いことも、名称を正しく答えることも、状態間の関係を理解した直接の証拠にはなりません。
逆に、表示を見ながら目的の作業ができることには、その条件での実用上の価値があります。すべての利用者が内部処理を暗記する必要があるとはいえません。

「どの情報を見せるか」は、名称、保存先、状態の変化のうち、何を利用者が判断する必要があるかと関係します。
この例はその違いを説明するためのもので、情報の削除・常時表示・折り畳みの採否や、最適な図の形式を実証するものではありません。
