# 視覚的な優先順位

## 目的と適用条件

配置・余白・文字の大きさや太さなどを通じて、読み始める位置、情報同士の関係、相対的な強調を伝えます。同時に複数の情報を示す画面で、必要な情報を見つけ、内容の構造を理解できるようにするために使います。

次の三つは分けて考えます。

| 種類 | 決めること |
| --- | --- |
| 判断上の優先度 | 目的や業務の規則に照らして、何を優先すべきか |
| 情報の構造 | 何が親・子・同じ階層で、どのまとまりに属するか |
| 視覚的な強調・読む入口 | どこに気づき、どこから読めるようにするか |

大きく見せたものが、業務上も最重要になるわけではありません。同じ階層の見出しも、内容の業務上の重要度が等しいことを自動的には意味しません。

以下の手順と例は **Mimic の提案**です。ブランディング、個別の Design System、個人の好みは扱いません。

## AI が確認する入力

- 利用者の目的と、判断上の優先度を決める条件・規則。
- 選ばれた情報、必要な補足、例外や注意事項。
- 親子関係、同じ階層、グループ、比較して読む必要がある情報。
- 利用する端末や画面幅、文字の拡大、読み上げなどの利用条件。
- 利用者が読み始める候補と、強調を弱めても発見できる必要がある情報。

## 判断手順

1. **目的から、読む入口の候補を決める。** 次の行動、比較対象、全体把握など、何を最初に理解する必要があるかを確かめる。データの表示順や現在の文字サイズから重要度を逆算しない。
2. **構造と強調を分けて指定する。** 見出しの階層・所属・比較関係を整理し、そのうえで何へ注意を向けるか決める。
3. **必要な手掛かりを与える。** 配置・近接・余白・文字表現などで関係や相対的な強調を伝える。特定の装飾や数値を、全画面の共通解にはしない。
4. **弱めた情報も確認する。** 補足が読めるか、例外や判断を左右する情報が見つかるか確かめる。項目を減らす代わりに、必要な本文を読みにくくしない。
5. **別の利用条件でも意味を伝える。** Web では見た目だけで見出しにせず、内容を表す見出しと論理的な階層を用意する。各プラットフォームで適切な意味付け・読み順は別途確認する。
6. **目的の達成を確かめて戻る。** 意図した入口に気づけるか、構造や重要度を誤解しないかを確認する。強調で解けない場合は、情報の選定や分類を見直す。

## AI が返す内容

| 内容 | 残すこと |
| --- | --- |
| 読む入口の案 | 何から読めるようにするか、どの目的・条件によるか |
| 構造と強調 | 親子関係、同じ階層、強調する情報を分けて説明 |
| 表現の理由 | 配置や余白などが、どの関係・相対的重要度を伝えるか |
| 適用の限界 | 弱めても読める必要がある情報、端末・読み上げでの確認、仮定と検証方法 |

## 説明用の例

[グルーピングの例](grouping.md)と同じ、架空の4件を使います。現在は当日の9:00、すべて未完了です。

| 所属 | 日時 | 内容 |
| --- | --- | --- |
| 仕事 | 今日 10:00 | 会議 |
| 仕事 | 今日 17:00 | 資料の提出期限 |
| 私用 | 明日 14:00 | 歯科の予約 |
| 私用 | 週末・時刻未定 | 旅行の準備 |

### 条件 A：次の時刻付き予定を知りたい

「今日」の中の10:00の会議を、時刻と内容を一緒に読み始められる位置に置く案を考えます。17:00の提出期限も読める状態で残します。ここで会議を入口にするのは、次の時刻付き予定だからです。会議が提出期限より業務上重要だと判断したわけではありません。

提出に必要な準備時間や失敗の影響は不明です。「今から取り組むべき仕事」を決める目的へ変わった場合、入口も判断材料も見直します。順番や大きさだけで、その問いへ答えたことにしません。

### 条件 B：仕事と私用を分けて全体を把握したい

「仕事」と「私用」を同じ階層の見出しにし、各予定をその下へ置く案を考えます。**両グループへ同程度にアクセスする必要があると仮定**して、どちらも見つけやすくします。日時は各項目に残し、グループの境界を余白などで伝えます。

これは両グループの負担や業務上の重要度が等しいという意味ではありません。予定の所要時間や影響が不明なので、件数から時間配分を判断することもできません。

両条件の表現は、読む入口と構造を説明する案です。全利用者が必ずその順で見る、という検証結果ではありません。

## 未検証事項

- 意図した読む入口に気づき、判断上の優先度や情報の階層を誤解しないか。対象の課題を用いた確認が必要。
- 小さい画面、文字の拡大、読み上げでも、関係と内容が伝わるか。実際の表示や読み順はまだ作成・確認していない。
- 弱めた補足・例外が、必要な場面で見つかるか。見た目の強弱だけで重要な材料を見落とさないか。
- Web、iOS、Android の各環境での具体的な意味付け・実装・支援技術への対応。
- 出典の現行内容・リンク到達性。適用時の原文再照合は未実施。
