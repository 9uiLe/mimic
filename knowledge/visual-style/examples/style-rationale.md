# 同じ要件から表現を分ける説明例

これはMimicが作成した架空の地域図書館のイベント予約UIの例です。原典の作例や、採用を推奨する完成案ではありません。見た目の選択理由の説明に焦点を置き、色値や文字設定の具体案は作りません。

## 共通する要件と意図

利用者はイベントの対象年齢・日時・空席を確認し、詳細を読んで予約します。Webとスマホで同じ内容を扱い、画面幅や文字サイズが変わっても必要情報と操作を保つことが要件です。図書館側は、地域の人が参加を考えやすい表情を望み、それを「親しみやすい」と言っています。

この意図だけでは、使う画像や構図は決まりません。例えば、次の二つは検討できる表現案です。どちらが要件を満たすか、どちらが望む印象に近いかは、この文章だけでは確定しません。

| 説明すること | イラストを中心にする案 | 写真を中心にする案 |
| --- | --- | --- |
| 表す内容 | 読書や工作の題材を、同じ線の描き方のイラストで表す | 会場や活動の様子を、画角や扱いをそろえた写真で表す |
| 選択の意図 | 題材を描く表現を、イベント間に共通する特徴にしたい | 実際の場所や活動の様子を、見た目の特徴にしたい |
| 表情を変える部分 | イベントの題材に応じて描く対象を変える | イベントに応じて写す対象を変える |
| 共通に保つ部分 | 日時・対象年齢・空席・予約操作の役割と表示の関係 | 日時・対象年齢・空席・予約操作の役割と表示の関係 |
| 未確認の条件 | 絵の題材が伝わるか、絵が必要情報と競合しないか | 適切な写真を継続して用意できるか、縮小や切り取りで伝えたい内容を失わないか |

二つの案は、単に「親しみやすい画像を使う」と言うより、何を描き、どの部分をそろえ、どこを変えるかを具体的に説明しています。一方、イラストなら親しみやすい、写真なら信頼できる、といった対応は仮定していません。

## 印象の意図と成立条件を分ける

どちらの案でも、対象年齢や空席を画像だけで伝えることは、この作例の共通要件を保つ説明になりません。必要情報と操作を残した上で、画像の表情を検討します。説明できる選択理由があっても、実際の読み取り、文字拡大時の表示、利用者が受け取る印象まで確認済みにはなりません。

この例は、同じ目的から複数の表現候補を説明できることと、意図した印象がそのまま実証された結果ではないことを示します。実際の採用には、既存の図書館の表現、用意できる素材、対象となる内容や利用者を踏まえた確認が残ります。
