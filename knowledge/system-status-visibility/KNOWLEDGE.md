# システム状態の可視性

## 定義

システム状態の可視性（visibility of system status）は、利用者が作業を進めるのに必要なシステムの状態を、適切なタイミングのフィードバックから把握できるようにする考え方です。Nielsen Norman Groupのユーザビリティ・ヒューリスティックの一つです。ここでいう可視性には、支援技術を通じて状態を知ることも含みます。

状態は、その時点で何が起きているかを指します。フィードバックは、その状態や操作の結果を伝える応答です。たとえば保存では、入力の受付、処理中、確定、失敗、結果がまだ分からない状態を、利用者が次に取る行動に応じて伝え分けます。

## 兆候と見分け方

| 兆候 | 見分けるために調べること |
| --- | --- |
| 押した直後に何度も押す | 受付が伝わるより前に押し直しているか。処理が遅いのか、最初の入力が届いていないのか。 |
| 完了したはずなのに画面を開き直す | 完了した対象や範囲が分からないのか、完了表示と再読込後の値が食い違っているのか。 |
| 失敗したまま次へ進む | 失敗を認識できなかったのか、認識しても復帰する方法が分からなかったのか。後者は[エラーからの回復](../error-recovery/KNOWLEDGE.md)を併せて読む。 |

この表は調べ始めるためのMimicの整理です。一つの行動は複数の理由から生じます。直前の操作、実際の状態遷移、本人が何が起きたと思ったかを照合します。

## 状態を伝える場所とタイミング

操作の近くで状態が分かれば、作業を続けながら確かめられます。Appleは、通常の状態は作業中に参照できる場所に置き、予期しないデータ損失のように重大な内容は中断する通知も検討するよう勧めています。IBM Carbonは、局所的な処理を知らせる方法として、処理中・成功・エラーを表すインライン表示を例示しています。

適用時は、どの操作を受け付けたかと、何が実際に完了したかを明らかにします。たとえば下書きを端末に書き込んだだけで、サーバーへの同期が終わっていなければ、利用者に両者の違いが関係する場面では「この端末に保存」「同期中」などと範囲を示せます。待ち時間や重要度によって必要な表示は変わります。

## 適用した結果を確かめる

Webでは、WCAG 2.2の達成基準4.1.3に該当するステータスメッセージを、フォーカス移動なしに支援技術が提示できるようにします。動的メッセージを使う場合は、視覚上の表示と、支援技術に伝わる内容・順序・重複を対象の環境で調べます。機械検査では、遅延・成功・失敗の条件で実状態と表示が一致するかを確かめられます。利用者が結果を理解し、次に進めたかは[ユーザビリティテスト](../usability-testing/KNOWLEDGE.md)の課題として観察できます。

[インタラクションデザイン](../interaction-design/KNOWLEDGE.md)は、状態を伝える場面を含め、行為と応答のつながり全体を扱います。どの状態をどう見せるかは、利用者の作業、結果を誤認したときの影響、対象プラットフォームで決めます。
