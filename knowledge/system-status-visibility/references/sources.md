# システム状態の可視性の出典

| 出典 | 確認箇所と本文で使う範囲 |
| --- | --- |
| [Aurora Harley — Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/) | 冒頭のヒューリスティック、Appropriate Feedback、Communication Creates Trust。何が起きたかを適時に伝え、次の判断を助けるという実務原則。特定の表現の効果を測定した実験ではない。 |
| [Apple Human Interface Guidelines — Feedback](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/feedback.md) | Discussion、Best practices。重要度と中断、操作対象の近くの状態、複数の伝達経路。Appleのプラットフォーム指針として読む。 |
| [IBM Carbon Design System — Inline loading](https://carbondesignsystem.com/components/inline-loading/usage/) | When to use、Placement、Behaviors / States。ユーザー操作に伴う局所的な処理、完了、エラーの表示例。Carbonの部品仕様として読む。 |
| [W3C — Understanding WCAG 2.2 SC 4.1.3 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | Success Criterion、Intent、Examples。マークアップ言語で実装したコンテンツにおいて、成功・結果・待機・進捗・エラーなどの該当する状態メッセージを、フォーカスを受けずに支援技術が提示できる要件。 |

保存・同期、再読込、同じ操作を繰り返す理由の候補は、これらの考え方を当てはめたMimicの例です。各例は、対象製品の挙動と利用者の行動を照合するために使います。
