# ユーザーニーズ

## 概念

ユーザーニーズは、利用者が望む成果を得るために、サービスが満たす必要のある内容です。
GOV.UKの指針では、利用者の問題に焦点を置き、調査の根拠に基づいて説明します。
特定の機能や画面形式を先に指定することとは区別します。

## 利用者・目的・状況

何をしたいかと、その理由を記述し、必要なら誰のニーズか、何がきっかけか、どのような状況の制約があるかも示せます。
実際または想定する利用者の観察・インタビュー、既存の記録、支援する担当者への調査などが理解の材料になります。
関係者の意見だけで根拠がない内容は、調査で確かめる仮定として扱います。

## ニーズと解決案の違い

以下は区別を説明するMimicの架空例です。調査結果ではありません。

| 記述 | 表していること |
| --- | --- |
| 期限までに手続きを終えるため、必要な時期に気付ける必要がある | 利用者が達成したいことと、そのための必要 |
| プッシュ通知を送る | 必要を満たすための解決案の候補 |

機能要望も調査の手掛かりになりますが、要望の存在だけでは、その解決案が適切かは分かりません。

## 要求を具体化する際の位置付け

GOV.UKは、ニーズを比較的広く安定したもの、[ユーザーストーリー](../user-stories/KNOWLEDGE.md)を具体的な機能・内容や受入条件を伴う仕事の単位として説明します。
対応関係を保つことで、どの仕事がどの必要に関わるかをたどれます。
表現の型に当てはめただけでは、ニーズが確認できたことにはなりません。

[ユーザーリサーチ](../user-research/KNOWLEDGE.md)は理解の根拠を得る活動です。
[HEART](../heart-framework/KNOWLEDGE.md)は、目標を測定へ結び付ける枠組みです。指標そのものをニーズとは呼びません。
