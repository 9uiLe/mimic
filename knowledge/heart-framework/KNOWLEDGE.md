# HEARTと目標・シグナル・指標

## 概念と背景

HEARTは、Rodden、Hutchinson、FuがCHI 2010の論文で示した、利用者の経験に関する指標を考える枠組みです。
Googleの大規模なWeb製品での実務を背景とします。
同論文は、カテゴリの枠組みと、目標を測定へ結び付けるGoals-Signals-Metricsを説明します。

## HEARTのカテゴリ

| カテゴリ | 扱う内容 |
| --- | --- |
| Happiness | 満足や使いやすさの認識など、利用者の態度 |
| Engagement | 一定期間の利用頻度・深さなど、製品への関与 |
| Adoption | 新しい利用者が利用を始めること |
| Retention | ある時点の利用者が、その後も利用すること |
| Task success | 課題の達成、所要時間、エラーなど |

これらは指標を選ぶ観点です。全カテゴリを採用する必要はありません。
何を利用開始や継続と数えるかも、製品と目標に応じて変わります。

## 目標から測定へ

| 要素 | 意味 |
| --- | --- |
| Goals | 製品や機能が、利用者の経験について達成したいこと |
| Signals | 達成または失敗を示すと考えられる行動・態度の兆候 |
| Metrics | 兆候を継続的に追える比率・平均などへ具体化した指標 |

数字を先に選ぶと、その数字が目標の何を表すか曖昧になります。
件数の増加も、利用者数の増加など別の要因で起きます。
論文は、目標への感度と対応、正規化、記録漏れなどの測定上の条件を扱います。

## 適用範囲と関連概念

指標は、[ユーザビリティテスト](../usability-testing/KNOWLEDGE.md)や現地調査を補うもので、初期の調査を置き換えません。
HEARTは、全製品の最適な指標や数値目標を定める規格ではありません。
[ユーザーニーズ](../user-needs/KNOWLEDGE.md)や[受入条件](../user-stories/KNOWLEDGE.md)と、測定値そのものも区別します。
