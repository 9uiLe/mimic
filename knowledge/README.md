# AI向けの入口

Mimicは、デジタルUIに関する共通知識を提供します。利用者の目的と案件の条件を確かめ、必要な知識を各工程の判断に使います。案件固有の仕様・設計書・レビュー資料は利用側の案件に置きます。

Repositoryの掲載・編集・採用方針は [利用ガイド](../guideline/README.md)、AIの作業指示は [AI向けの作業ガイド](../guideline/ai.md) に従います。知識の説明を編集するときは、原典への忠実さと概念の明確さを確認します。案件の仮定や独自の提案は、区別しただけで採用済みの共通知識になるものではありません。

## 正本と人向け資料

以下の3ファイルが、判断条件・手順・根拠・限界の正本です。[人向けREADME](../README.md) は正本から作る説明であり、正本の代わりとして参照済みに数えません。

| ID | 正本 | 主な問い |
| --- | --- | --- |
| `decision-material-selection` | [判断材料の選定](decision-material-selection.md) | 目的に必要な判断材料と、表示する情報をどう選ぶか |
| `grouping` | [グルーピング](grouping.md) | 利用目的に沿って、何を一緒に扱うか |
| `visual-hierarchy` | [視覚的な優先順位](visual-hierarchy.md) | 読む入口、関係、相対的な強調をどう伝えるか |

最小構成でこの3件を利用するときは、索引だけで判断せず、3本文の適用条件・理由・出典の支持範囲・未検証事項まで確認します。大規模な知識集合の自動選択・検索方式は未定義です。

## 参照と判断

1. 利用者・目的・必要な判断・間違いの影響を整理する。未指定の条件は仮定として示す。
2. 指定された版、実際の参照元、参照対象の未コミット変更を確認する。本文を確認できた範囲と、読めない箇所・版の不一致を報告する。パスや要約を受け取っただけで本文を参照したとは扱わない。
3. 出典で支えられる指針、Mimicの提案、説明用の仮定、案件固有の仕様を区別する。
4. 情報選定・グルーピング・強調を往復して検討する。固定の件数や例の配置を一般則にしない。知識が足りない判断は、その不足を明記する。
5. 詳細な判断と、人が理解・判断するための説明を分けて返す。参照できたことと、知識が有効に働いたこと、実際の使いやすさを確認したことは、それぞれ区別する。

## 人向けの説明

Mimic自体の説明には、知識の全体像・関係・使う条件・根拠・確かさと、正本への参照を示します。採用が未決の更新案には、判断が必要な点を添えます。

案件の成果物では、詳細な要件・設計・根拠を案件側の正本に残します。人向けには、全体像、設計した事実、理由、未確定事項と判断が必要な問いを取り出し、元の記述へ戻れるようにします。重要な制約や未確認事項は短縮のために落としません。

「判断材料の選定」では、[人向けの閲覧ページ](../prototypes/decision-material-selection/index.html)と[AI向けの全文](../prototypes/decision-material-selection/ai.md)を、正本Markdownから生成します。編集対象は正本だけです。生成物の更新・確認方法は[Repositoryの入口](../README.md#判断材料の選定の試作品)に記載します。他の2件の知識は現在のMarkdownをそのまま参照します。

[研究案](../prototypes/decision-material-selection/draft.md)と[その閲覧ページ](../prototypes/decision-material-selection/research/index.html)は、判断軸を拡張する採用前の更新案です。共通ルールとして参照する現行正本とは区別します。採用が確認されるまでは、現行正本を置き換えたと扱いません。研究案も1つの編集元から両方の出力を生成し、[共通の表示規約](../prototypes/knowledge-view.md)を使います。

## 記録と更新

既存のYAML項目 `id`・`title`・`status`・`version`・`scope`・`related` を使います。版は各正本の`version`を確認します。現在は3件とも `status: proposed`、`scope: general-digital-ui` です。整理案であり、実利用での有効性の検証結果を意味しません。

新しい知見は、根拠・適用条件・例外・限界を添えた更新案にします。案件固有の事実や単一例の成功を一般則にせず、既存知識で説明できる場合は新規項目を増やしません。採用を確認してから正本を更新し、人向けの説明と参照するID・版・状態も見直します。

各本文にある出典の照合状況と適用範囲を確認し、未確認を確認済みとして扱いません。AIが読み違える場合は、原典と文章を照合して説明や補足を修正します。実画面の使いやすさや利用側の自動参照は、個別のUI・機能として確認します。これらの効果測定を、知識の採用に一律に求めません。
