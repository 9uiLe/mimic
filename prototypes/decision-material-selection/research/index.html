何を、なぜ提示するかを説明する

#

利用者の目的から必要な判断材料を導き、単独の情報で足りるか、組み合わせや要約が必要かを比較します。目的は、正しく判断でき、重要な条件を見落とさず、読む・覚える・計算する負担を抑えることです。表示項目の少なさを目的にしません。

提案

これは旧版 0.1.1 に対して作成した、未採用の研究資料です。出典を踏まえてまとめた5つの判断軸と手順は Mimic の提案であり、現行の知識本文に採用したものではありません。現行の説明は概念を読む案内を参照してください。この研究資料はこの下書きだけを編集し、AI向け全文と人向けHTMLを生成します。

比較一覧、候補選択、状況確認などに使います。5つの軸は「目的と制約」「情報同士の関係」「意味の一貫性」「頭の中の処理」「情報への到達」です。適用条件を共有し、採用・不採用の理由を検証できるようにします。同じ条件に合う案が複数残る場合もあります。

限界・未確認

この試作は汎用UIへの応用案です。個別業務の優先規則、安全上・制度上の条件、ブランディング、個人の好みを決めるものではありません。理論を参照しただけでは、情報選定の正しさや実際の使いやすさは保証できません。

判断の進め方へ判断案と選定理由へ未検証事項を確認する

最初に確かめる条件

#
  • 誰が、どんな状況で、何を決めるか。人が選ぶのか、AIの選択を確認するのか。
  • 正しい判断の条件と、誤り・見落としの影響。通常・境界・例外で規則が変わるか。
  • 情報の意味・単位・相互依存・重複・欠損・鮮度・信頼性。
  • 一緒に比較する必要のある情報と、必要になってから調べられる情報。
  • 一覧の範囲、絞り込み、並び順、見出しなど、各項目の外から既に伝わる文脈。

答えがない条件は仮定として残します。結論が変わる条件を推測で埋めた場合、仮定が成立する範囲の候補案と、確かめる方法を返します。未確認の情報を「不要」とは扱いません。

5つの軸で提示案を比較する

#
  • 1. 目的と制約に対応しているか
  • 2. 単独の値ではなく、必要な関係が分かるか
  • 3. 名前・単位・文脈の意味が揃っているか
  • 4. 頭の中で何を覚え、計算し、照合するか
  • 5. 必要な情報に、必要なとき到達できるか
  • 判断案を作る流れ

以下では、出典が支える考え方と、それを情報選定へ使う Mimic の提案を区別します。軸ごとの点数を足して自動的に最適案を出す方式ではありません。

1. 目的と制約に対応しているか

問い：何が分かれば、目的に合う判断が成立するか。 目的、満たす条件、その条件を確かめる情報をつなぎます。単一の情報で成立するなら単一でよく、複数条件があるなら必要な組み合わせを候補にします。まれな条件も、結論を左右するなら頻度だけでは外しません。

出典の考え方： Ecological Interface Design（EID）は目的と手段の関係を扱います。Mimic の応用案： 情報の一般的な重要度ではなく、今回の目的への寄与で採否を説明します。

根拠の範囲

EIDの主な対象は複雑な産業システムです。この考え方を一般の比較一覧へ使うことは応用仮説であり、論文がこの選定手順や項目数を実証したわけではありません。出典は「出典と適用の境界」の EID を参照してください。

2. 単独の値ではなく、必要な関係が分かるか

問い：差、釣り合い、基準からのずれを見なければ判断できないか。 値だけで判断できなければ、比較相手・基準・差分などを合わせます。関係を表す一つの指標も候補ですが、条件や不確かさを失う要約は採りません。

出典の考え方： EIDは目的に関係する情報と、下位の要素データを区別します。Mimic の応用案： 二つの時間から「余裕」を示す案と、二つを並べる案を比べます。任意の計算式が妥当になるわけではなく、式の意味と成立条件を別に確かめます。

3. 名前・単位・文脈の意味が揃っているか

問い：利用者は、この値や区分を意図どおりに解釈できるか。 専門語や要約値を使うなら、名称・単位・定義・対象範囲を確認します。名称だけでは曖昧なら説明を組み合わせます。全体見出しへ移す情報は、その範囲が伝わる場合に限り繰り返しを省けます。

出典の考え方： Normanの著者解説は、文脈と概念モデルが意味の理解に関わると論じます。Mimic の応用案： 「余裕」は経過時間ではなく作業可能時間の差だと伝え、利用者の言葉で説明してもらいます。名称を付けたことだけでは理解を確認したことになりません。

4. 頭の中で何を覚え、計算し、照合するか

問い：表示を減らしたことで、記憶や暗算を増やしていないか。 元情報を同時に並べる案と、関係を外に表した要約を使う案を比べます。内訳の妥当性を確かめる仕事なら、元情報を見せる案が適する場合もあります。

出典の考え方： ZhangとNormanは、外に表した情報が記憶補助にとどまらず、課題の進め方を変え得ることを論じます。Mimic の応用案： 要約で暗算を減らす案を候補にし、誤解や内訳確認の負担も合わせて確かめます。

根拠の範囲

参照した研究の実験はハノイの塔を用いています。仕事一覧で要約案が速い・正確・低負担という結果を得たものではありません。

5. 必要な情報に、必要なとき到達できるか

問い：詳細へ移した情報を、必要な人が発見できるか。 同時比較する情報を別々に隠す案や、全員が必要とする条件を隠す案は見直します。条件付きで表示するなら、その条件を検出でき、表示の変化が伝わる必要があります。

出典の考え方： GOV.UKのアコーディオン指針は、全員が必要な内容を隠すことを避け、利用者による確認を求めています。Mimic の応用案： 常時表示と詳細送りを比較し、到達できなければ常時表示などへ戻します。すべての折りたたみを禁止する根拠ではありません。

判断案を作る流れ

  1. 利用者の目的、成功条件、誤りの影響を置き、未確定の条件を明示する。
  2. 条件と情報の対応を示す。単独で足りる情報、組み合わせが必要な情報、今回は使わない情報を、理由と条件付きで整理する。
  3. 元情報を並べる案、意味を保つ要約案、文脈へ移す案を必要な範囲で作る。各案の常時表示・必要時表示・詳細を示す。
  4. 5つの軸で成立条件と弱点を比較する。必要な判断ができない案を戻し、成立する複数案は利用者の課題で比較する。
  5. 採用候補、代替案、仮定、保留と確認方法を残す。条件が変わったら、対応する情報と案を見直す。

確認するのは、目的に合う判断の正しさ、重要な見落とし、必要情報の発見、解釈・記憶・計算の負担です。特定の候補数の検証や、すべての組み合わせの総当たりを一律の完成条件にはしません。調査できていない部分があるなら、その範囲を示します。

情報との対応 どの条件に何の情報が必要か。単項・組み合わせ・関係の根拠

まとまりと優先順位へつなぐ

#
関連知識 行き来する理由
グルーピング 見出しや一覧の範囲が条件を伝えるなら、各行で繰り返す情報が変わる。まとまりから必要な情報を探せなければ選定へ戻る
視覚的な優先順位 選んだ情報の関係や重要度を伝える。強調だけで不足した情報を補うことはできない

架空の仕事一覧と判断規則

仮定

人が「今着手できる仕事のうち、期限までの余裕が最も小さいもの」を選ぶと仮定します。余裕は「期限までの作業可能時間 − 残り作業時間」です。見積もりは現在の状況に合い、欠損がなく、信頼でき、比較可能とします。他の業務上の優先条件は同じです。通常の一覧には着手不可の仕事も残ります。

仕事 着手可否 期限までの作業可能時間 残り作業時間 余裕
A 可 3時間 2時間 1時間
B 可 2時間 0.5時間 1.5時間
C 返答待ち・不可 1時間 0.5時間 0.5時間

この規則とデータなら仕事 A を選びます。目的と制約から着手可否と余裕が必要と分かり、情報の関係から二つの時間の差を調べます。作成日や依頼者名はこの仮定では選択に使いませんが、業務上の規則が変われば再検討します。

成立条件で比較する

案 1行の表示と文脈 この例での判断 採否の理由・条件
元情報を並べる 仕事名・着手可否・二つの時間 成立する候補 余裕を計算できる。内訳を同時に確認できるが、差の計算が必要
余裕へ要約する 仕事名・着手可否・余裕 成立する候補 差の計算を外に出せる。余裕の定義・単位を伝え、元の時間と計算方法へ到達できることが条件
一覧を着手可能だけに絞る 着手可能だけの一覧に、仕事名・余裕 条件付きの候補 要約案と同じ定義・単位・内訳への到達に加え、絞り込みが保証され、対象範囲が伝わるなら成立。着手可否の情報が消えたわけではない
全件から着手可否を省く 全件の一覧に、仕事名・余裕 成立しない 余裕だけで仕事 C を選ぶと着手条件に反する。情報への到達以前に必須条件が欠けている
残り作業時間を省く 仕事名・着手可否・作業可能時間 成立しない 小さい作業可能時間だけで仕事 B を選んでも、余裕が最小とは限らない。必要な関係を求められない

仮の試行案は「余裕へ要約する案」です。目的に関係する差を示し、暗算を減らす候補になるためです。ただし見積もりの妥当性も同時に確認する利用者には、元情報を並べる案が適する可能性があります。一覧を着手可能だけに絞る案は、一覧の範囲を保証できる場合の代替案です。表示項目の数だけでは採否を決めません。

次に何を確認すれば選べるか

元情報を並べる案と余裕へ要約する案で、通常と例外の課題を利用者に行ってもらい、選択の正しさ、重要な見落とし、所要時間、感じた負担を比較します。「余裕」の意味を本人の言葉で説明できるか、必要な内訳を発見できるかも観察します。一覧を絞る案では、対象範囲を取り違えないか確かめます。合格の水準は、誤りの影響と利用状況に応じて事前に置きます。

限界・未確認

ここまで確認したのは、仮定と表の数値に対する論理上の成立・不成立です。利用者実験は実施していません。要約案の速さや低負担、HTMLの理解しやすさ、他の目的への一般化は未確認です。

確かめていないことと、見直す条件

#
  • 5軸で、異なるAIが同じ条件を見落とさず、採否の理由を追跡可能にできるか。答えの一致率だけでは評価しない。
  • 候補に残った案の実際の正確さ、理解、負担、必要な情報の発見。例外を含む利用者の課題で確認する必要がある。
  • 余裕が負・同値・全件着手不可、見積もり欠損・低信頼の場合の業務規則と表示。値を黙って補完して順位を決めない。
  • 他の目的、情報の種類、利用者の経験へ適用できる範囲。今回の小さな論理例は汎用的な有効性の証拠ではない。
  • 人向けHTMLの実画面での仕上がり、狭い幅や文字拡大時の表示、キーボード操作、読み上げ、利用者の理解。静的な整合性検査だけでは判断できない。
  • 共通知識への採用。出典と応用仮説、保留を確認したうえで、人が採用を判断する。
