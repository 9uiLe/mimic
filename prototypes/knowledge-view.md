# 知識を読むページの表示規約

表示方式 `mimic-knowledge-view` の版は `1.0.0` です。「判断材料の選定」の現行版と更新案で共用します。新しい知識全体に対応した仕組みの完成を意味しません。

## 読者ができるようにすること

何を判断する知識か、今回使える条件は何か、なぜ提示案を採る・戻すのか、根拠と未確認はどこかを追えるようにします。HTMLはMimicの提供物として扱いますが、見栄えのよさだけで知識の有効性を証明したとは判断しません。

## 固定するものと、内容に合わせて変えるもの

固定するのは、ページ上部の識別と参照先、目次、本文の意味区分と表示順、見出し・本文・注記・表・手順の見た目、配色の意味、余白、狭い画面での配置規則です。目次は以下の役割IDを使い、見出しの言い換えでリンク先が変わらないようにします。

| 役割ID | 表示する内容・順番 |
| --- | --- |
| `purpose` | 目的と使う場面 |
| `inputs` | 使う前に確かめること |
| `procedure` | 判断の進め方 |
| `outputs` | 判断案と選定理由 |
| `related` | 他の知識との関係 |
| `example` | 例で確かめる |
| `sources` | 根拠といえる範囲 |
| `unverified` | まだ確かめていないこと |

可変なのは、題名、見出しの文言、本文、表の行数、手順数、例と小見出しの数です。知識を更新するたびに、AIが別の配色や配置を作りません。内容が増えればページの長さは変わります。新たな意味役割や表現が必要なら、表示規約と実装を明示的に改定します。

## 部品の使い分け

- 全体像と理由は見出しと本文で読み進められるようにし、すべてをカード化しません。
- 手順の順序は番号で示します。`procedure` 内の番号付きリストだけを手順部品にします。
- 同じ観点で比較する案や、出典と支持範囲の対応には表を使います。狭い幅での表は横へ読める領域にします。
- 提案・仮定・限界・根拠の範囲は、関係する段落の位置で注記にします。色だけに頼らず、種別名も表示します。太字や末尾位置から注記の意味を推測しません。
- 見出しから各区分へ移動できるようにし、正本・更新案の原文とAI向け全文へ戻る参照先を示します。情報が示す根拠のない関係図は作りません。

## 編集元と生成

知識はMarkdownの編集元にだけ記述します。現行の共通知識は `knowledge/`、採用前の研究案は試作の `draft.md` に置き、同じ版の内容を人用・AI用に書き分けて管理しません。採用時は現行正本を更新し、更新案を並行した共通ルールとして使い続けないようにします。

意味区分はH2直前の `<!-- mimic:section purpose -->`、小見出しの安定IDは `<!-- mimic:heading axis-purpose -->`、一段落の注記種別は `<!-- mimic:note proposal -->` の形で指定します。注記種別は `proposal`・`assumption`・`limitation`・`evidence-scope` です。本文をコメントや生成器へ重複して書きません。8役割は必須で、未知の役割・重複ID・未定義の注記は生成を止めます。

表示構造と生成規則は [生成器](../scripts/build-knowledge.ts)、書体・色・余白・画面幅への対応は [共通CSS](../scripts/knowledge-view.css) が実装です。CSSはHTMLへ埋め込み、外部配信の書体・画像・スクリプトに依存しません。知識の版と表示方式の版を分け、原文・CSS・生成器の指紋を生成HTMLへ記録します。

## 確認する範囲

AI向け全文も本文とメタデータを保持し、相対リンクだけは出力位置に合わせて補正して、同じ知識を指すようにします。元の文字列とのバイト一致を、参照先の正しさより優先しません。

この初期実装で補正するのは、段落・見出し・表にあるインライン形式の相対リンクです。コード中は補正しません。参照形式のリンク、複雑なブロック内の相対リンクなど、位置を確実に扱えない構文は明示的に失敗させます。

生成物の鮮度、両出力の知識本文の保持、相対リンクの参照先、見出し変更・長文・行数や手順数の増減でも役割IDと同じ表示方式が維持されることを自動検査します。未定義の役割を黙って別の見せ方に変えないことも確認します。

実画面の仕上がり・狭幅・文字拡大・操作・読み上げは実物での確認が必要です。内容理解は、読者に「この知識の目的」「要約案と着手可否を省いた案の違い」「一覧を絞る案を使える条件」「未確認のこと」を説明してもらい確かめます。静的検査や作成者だけの確認で、これらを合格扱いしません。
