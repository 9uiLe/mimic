# 知識を読むページの表示規約

表示方式 `mimic-knowledge-view` の版は `2.0.0` です。「判断材料の選定」の正本と、採用前の研究資料の閲覧ページで共用します。「グルーピング」と「視覚的な優先順位」はMarkdownを参照します。

## 読者ができるようにすること

知識の定義、関連する概念との違い、説明の対象範囲、出典を、本文の構成に沿って読めるようにします。版と採用状態を示し、閲覧できることを正式採用と取り違えないようにします。HTMLの生成検査は、配信する文章とリンクの検査です。知識の正しさや使いやすさを実証するものではありません。

## 通常の知識本文

通常のMarkdownでは、H2の章立てと順序をそのまま表示し、同じ見出しを目次に使います。知識の説明に、判断手順・成果物・未検証事項などの区分を追加することはありません。H1はメタデータの題名と一致する一つに限り、本文はH2から始めます。各章には本文を置きます。

H2と小見出しのリンクIDは、見出しの文字から生成します。英字は小文字にし、記号を除き、空白をハイフンにします。同じIDには連番を付けます。見出しの変更時は、章へのリンクが変わる場合があります。目次とページ内リンクは同じ生成で更新します。

## 研究資料の表示

既存の研究資料では、章直前の `<!-- mimic:section purpose -->` などのコメントで、以下の8役割を指定します。この形式では8役割すべてを必須とし、役割に対応する表示順と目次を使います。通常の知識本文へ、この研究用の形式を強制しません。

| 役割ID | 表示する内容・順番 |
| --- | --- |
| `purpose` | 目的と使う場面 |
| `inputs` | 使う前に確かめること |
| `procedure` | 判断の進め方 |
| `outputs` | 判断案と選定理由 |
| `related` | 他の知識との関係 |
| `example` | 例で確かめる |
| `sources` | 根拠といえる範囲 |
| `unverified` | まだ確かめていないこと |

研究資料の小見出しには `<!-- mimic:heading axis-purpose -->` のように安定IDを指定します。一段落の注記には `<!-- mimic:note proposal -->` を使い、種別は `proposal`・`assumption`・`limitation`・`evidence-scope` です。未知の役割、重複ID、未定義の注記、不完全な構成は生成を止めます。コメントへ本文を重複して書きません。

## 共通の表示と部品

ページ上部の識別・版・状態と参照先、目次、見出し・本文・注記・表の見た目、配色、余白、狭い画面での配置を共通化します。内容を更新するたびに配色や配置を作り直しません。本文や章が増えれば、ページの長さも変わります。

- 説明は見出しと本文で読み進め、すべてをカード化しません。
- 通常の番号付きリストは通常のリストとして表示します。研究資料の `procedure` 内の番号付きリストだけを手順部品にします。
- 表は狭い画面で横へ読める領域にします。
- 研究資料の注記は関係する段落に置き、色に加えて種別名を表示します。本文の太字や位置から注記の意味を推測しません。
- 正本または研究資料の原文、AI向け全文、利用ガイドへの参照先を示します。

## 編集元と生成

知識は `knowledge/` のMarkdown、既存の研究資料は試作の `draft.md` を編集元にします。人用・AI用の文章を独立して管理せず、生成物を直接編集しません。表示構造と生成規則は[生成器](../scripts/build-knowledge.ts)、書体・色・余白・画面幅への対応は[共通CSS](../scripts/knowledge-view.css)が実装です。

CSSはHTMLへ埋め込み、外部配信の書体・画像・スクリプトに依存しません。本文へのHTML・画像の埋め込みは許可せず、HTTP・HTTPS以外の外部リンクを拒否します。知識の版と表示方式の版を分け、原文・CSS・生成器の指紋をHTMLへ記録します。

AI向け全文は本文とメタデータを保持し、相対リンクだけを出力位置に合わせて補正します。段落・見出し・表にあるインライン形式の相対リンクに対応し、コード中は補正しません。参照形式の定義や、リスト内の相対リンクなど、内容と参照先を正確に保持できない構文は生成を止めます。

## 確認する範囲

生成検査では、人向けHTMLに全内容があり、AI向け全文が同じ内容・メタデータ・参照先を保持すること、通常本文の章順、研究資料の役割、自己完結したHTML、生成物の更新漏れを確認します。Pagesの検査では許可したファイルだけを配信し、リンクが公開範囲内で解決することを確かめます。

GitHub Pagesの入口は、研究資料ではなく知識正本の閲覧ページを指します。知識の採否は各文書の状態で判断します。生成検査の成功を、出典の正しさや知識の正式採用として扱いません。
