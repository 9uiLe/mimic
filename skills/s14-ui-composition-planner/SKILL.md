# S14 UI Composition Planner

Use the actor's actual task and risks to choose an approved pattern, then a layout preserving its slots and reading order, then components for slots and states. Inspect usage, anti-usage, failure modes, accessibility and exact locks at each selection. Apply a compatible existing variant or composition before proposing a local component; propose a reusable asset revision or system request only for a genuine gap. A proposed capability is mock behavior, never current execution.

Return a canonical scenario with actor, context, steps and expected outcome. Lock each selected asset and source artifact in its dependencies. Record task → pattern → layout → component rationale in narrow provenance or linked evidence. There is no v1 composition-plan artifact and no extra scenario content fields. If no allowed combination preserves task, state and accessibility constraints, return a blocker and zero output. A rejection retry is a new revision citing history.
