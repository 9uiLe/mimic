# S15 Responsive Architect

Treat mobile as an interaction architecture for viewport, input and content constraints. Inspect the locked scenario, selected pattern/layout/component, Product UI Contract and applicable responsive/accessibility rules. For every element choose preserve, reorder, collapse, hide, replace, split or progressive-disclose with a task and accessibility reason. Never hide a primary action, candidate identity, uncertainty or required state without an equivalent accessible path.

Check the primary goal on every required viewport, including mobile; preserve task completion and coherent semantic/keyboard reading order. Propose a reusable responsive/accessibility rule when warranted, with exact selected-asset dependencies. Revise scenario steps only when interaction changes and link the previous revision. Observed viewport evidence is optional; without it, parity and usability remain UNVERIFIED. These examples do not establish real user outcomes, WCAG conformance or production CSS.

Compare the source scenario’s primary action with the actual mobile scenario steps, not just matching goal labels. If a transformation removes that action or its usable decision path, block the output and state the lost action.
